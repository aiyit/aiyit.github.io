6주차 · Module 06

기능 블록 다이어그램(FBD) 실습

논리·연산·타이머를 연결하고 실행 조건과 상태를 함께 읽는다

오늘의 학습 목표

  • FBD 블록의 입력·출력·자료형을 읽는다.
  • AND·OR·NOT, 연산·비교 기능을 연결한다.
  • EN/ENO와 기능의 논리 입력을 구분한다.
  • TON과 독립 인스턴스로 지연 표시기를 구성한다.
  • 가상 시간·조건 해제·Reset 시험으로 결과를 확인한다.

선수학습: 1~5주차 / 브라우저만으로 개념 학습 가능 / 선택 실습: 지원되는 TIA Portal·시뮬레이터 / 실제 I/O·출력·안전 제어 제외

1

FBD란? — 기능과 신호를 연결해서 표현하기

FBD(Function Block Diagram)는 논리·연산·비교·타이머·기능 호출을 블록과 연결선으로 표현하는 그래픽 언어입니다. 각 블록의 입력값을 처리하여 출력값을 다음 블록이나 태그로 전달합니다.

입력 태그→논리·연산 블록→결과·상태→출력 태그

LD가 접점·코일의 관계를 강조한다면 FBD는 기능 단위와 데이터 흐름을 읽는 데 유용합니다. 표현 방식이 달라도 논리·자료형·상태·호출 규칙을 정확히 정해야 합니다.

FBD는 언어, FB는 상태를 가질 수 있는 프로그램 구성 단위입니다. FBD로 FC·FB 등을 작성할 수 있으며, SCL로도 FB를 작성할 수 있습니다.
이번 교안의 도식은 문자로 그린 개념도입니다. TIA Portal로 가져오는 FBD 프로젝트 파일이 아닙니다. 실습은 내부 DB와 가상 입력만 사용합니다.
2

+---------------+
InputA ------>| IN1           |
InputB ------>| IN2   기능     |----> Result
              +---------------+

확인 순서: 기능 이름 -> 입력 역할/형식 -> 출력 역할/형식 -> 호출 조건
항목읽어야 할 내용
블록 이름AND·ADD·비교·TON 등 어떤 기능인가?
입력 파라미터조건·설정값·계산값 중 무엇인가?
출력 파라미터결과·완료·유효성·경과값 중 무엇인가?

상태/인스턴스이전 호출의 값이 필요한 기능인가?
실행 조건매 스캔 실행인가, EN이 있는 조건부 명령인가?

그림상 가까운 위치에 있거나 선이 교차한다고 모두 연결된 것은 아닙니다. 실제 편집기의 접속점·파라미터 연결 상태를 확인하고 컴파일로 자료형·미연결 오류를 점검합니다.

3

실습 1 — AND·OR·NOT로 허가 논리 구성

가상 입력 A 또는 B 중 하나 이상이 TRUE이고 Enable=TRUE이며 Blocked=FALSE이면 Lamp를 켜는 조합 논리입니다.

A --------+ 
          [ OR ]---+
B --------+       |
Enable -----------[ AND ]----> Lamp
Blocked --[ NOT ]-+

Lamp = (A OR B) AND Enable AND NOT Blocked
ABEnableBlockedLamp
FALSEFALSETRUEFALSEFALSE
TRUEFALSETRUEFALSETRUE
FALSETRUETRUEFALSETRUE
TRUETRUETRUETRUEFALSE
TRUETRUEFALSEFALSEFALSE
Blocked는 차단 조건이 TRUE라는 뜻입니다. 태그 이름·TRUE의 의미를 정의하고 NOT을 적용합니다. 부정 기호만 보고 물리 NC 접점과 같다고 생각하지 않습니다.

같은 식을 LD 또는 SCL로 표현할 수도 있습니다. 언어를 바꾸더라도 모든 입력 조합의 결과를 비교합니다.

4

실습 2 — 연산·변환·비교 연결

가상 압력 원시값 0~27648을 0~10bar로 환산하고 7bar 이상인지 판정합니다. 이는 특정 모듈을 보편적으로 표현하는 값이 아니라 3주차에서 사용한 교육용 가정입니다.

Raw(Int) -> INT_TO_REAL -> DIV(27648.0) -> MUL(10.0) -> Pressure(Real)
                                                              |
                                                   >= 7.0 -> HighPressure
입력환산값HighPressure
00.0barFALSE
138245.0barFALSE
2764810.0barTRUE

입력이 정상 범위인지와 채널 품질이 유효한지를 먼저 검사합니다. 경계 밖 값은 정책에 따라 무효 처리하고, 숫자 결과와 Valid를 함께 제공합니다. 무효 데이터가 이전의 고압 상태를 덮거나 정상값처럼 사용되지 않도록 정합니다.

단순 EN 연결로 계산을 건너뛰면 이전 출력 숫자가 남을 수 있습니다. 무효 시 기본값·유효성·출력 정책을 별도로 명시해야 합니다. 정수 나눗셈 후 변환하지 말고 필요한 형식으로 변환한 뒤 계산합니다.
5

EN/ENO — 호출 허가와 논리 데이터는 다르다

EN/ENO가 있는 명령에서 EN은 실행 허가 입력이고 ENO는 실행 상태를 전달하는 출력입니다. 일반적인 설명으로 EN=TRUE이면 명령을 실행하고 처리 오류가 있으면 ENO가 FALSE가 될 수 있습니다. 정확한 조건은 해당 명령의 도움말을 확인합니다.

대상의미혼동 방지
EN명령/블록 실행 허가공정 입력이나 타이머 IN과 동일하지 않음
ENO명령 실행에 관한 상태기계가 정상 운전했다는 실제 피드백 아님
논리 IN기능이 계산할 데이터/조건FALSE도 정상적으로 처리해야 할 입력일 수 있음
TON의 IN시간 측정의 시작·해제 조건IN=FALSE로 호출해야 초기화 동작을 평가

모든 블록에 동일한 EN/ENO 동작이 있는 것은 아닙니다. EN이 없는 명령은 입력이 FALSE라는 이유만으로 호출 자체를 생략하는 것이 아닙니다.

“블록을 실행하지 않음”과 “블록을 실행하면서 IN=FALSE를 전달함”은 다릅니다. 상태를 가진 기능에서는 차이가 특히 중요합니다.
예를 들어 타이머를 Permit=TRUE일 때만 호출하도록 만들면 Permit이 FALSE인 호출에서 타이머를 초기화하는 처리를 기대하기 어렵습니다. 매 스캔 호출하고 IN으로 조건을 제어하는 구조를 먼저 학습합니다.
6

TON 타이머 — 입력·설정시간·결과·경과시간

TON (고유 인스턴스)
조건(Bool) ------> IN             Q ----> 완료(Bool)
설정(Time) ------> PT            ET ----> 경과(Time)

IN이 PT 동안 TRUE로 유지되면 Q가 TRUE
IN이 FALSE이면 일반 TON의 Q와 경과 상태가 초기화
파라미터자료형학습 예시
INBoolSensor AND Enable AND NOT Reset
PTTimeT#2s
QBool지연 완료 표시
ETTime경과 시간 표시

TON은 상태를 저장해야 하므로 고유 인스턴스가 필요합니다. 같은 타이머를 서로 다른 두 센서에 공유하면 독립된 지연 처리가 되지 않습니다.

실제 PLC 타이머는 CPU의 시간 처리와 호출 규칙에 따라 동작합니다. 스캔 횟수에 무조건 일정 시간을 곱하는 방식으로 대체하지 않습니다. PT 중간 변경, 시간 자료형 범위, 고정밀 요구는 별도 검토합니다.
7

FB·인스턴스 DB·멀티인스턴스

개념역할예시
FB 형식재사용하는 기능의 정의FB_DelayIndicator
단일 인스턴스 DB하나의 FB 호출에 필요한 상태 저장DB_DelayA
또 다른 인스턴스 DB같은 형식의 독립 상태DB_DelayB
멀티인스턴스상위 FB의 인스턴스 안에 하위 상태 저장FB 내부 DelayTimer
Static호출 사이 저장되는 지역 데이터타이머 인스턴스 등

FBD로 TON을 삽입할 때 새 단일 인스턴스 또는 상위 FB의 멀티인스턴스를 선택할 수 있습니다. 실제 메뉴와 생성되는 자료형은 설치 버전·CPU에 따라 확인합니다. 멀티인스턴스는 상위 FB에 상태 저장 공간을 갖도록 구성합니다.

같은 FB 정의를 여러 번 재사용하더라도, 각 가상 장치는 별도의 인스턴스를 사용하면 상태를 독립적으로 유지할 수 있습니다.

Static 상태의 호출 간 기억과 전원 차단 후 Retain 정책은 별개입니다. 교안은 전원 복귀 후 타이머 상태 유지나 자동 운전을 요구하지 않습니다.

8

종합 실습 — 센서 ON 안정 확인 표시기

요구사항: Enable이 TRUE이고 Reset이 FALSE이며 Sensor가 TRUE로 2초 연속 유지되면 Lamp를 켭니다. 하나라도 조건이 사라지면 Lamp와 타이머를 초기화합니다. 완료를 저장하는 래치는 사용하지 않습니다.

구분이름자료형·설명
InputEnable, Sensor, Reset각각 Bool
OutputLampBool
OutputElapsedTime
StaticDelayTimerTON 멀티인스턴스
TempTimerInBool
Network 1: 타이머 입력 조건
Enable ------------+
Sensor ------------[ AND ]----> TimerIn
Reset ----[ NOT ]--+

Network 2: 매 스캔 호출, EN으로 건너뛰지 않음
TimerIn ---------> TON.IN
T#2s ------------> TON.PT
DelayTimer.Q ----> Lamp
DelayTimer.ET ---> Elapsed
  1. FBD 언어의 FB_DelayIndicator를 생성합니다.
  2. 위 표대로 인터페이스를 선언합니다.
  3. Network 1에서 AND·NOT을 연결하여 TimerIn을 계산합니다.
  4. Network 2에 TON을 넣고 DelayTimer 멀티인스턴스를 생성합니다.
  5. TON의 Q·ET를 Lamp·Elapsed에 연결합니다.
  6. 주기 프로그램에서 FB를 한 번 호출하고 전용 인스턴스 DB를 생성합니다.
  7. 실제 %I·%Q 대신 전역 DB LabFBD의 가상 태그를 연결합니다.
TimerIn은 매 호출 읽기 전에 계산되는 Temp입니다. 타이머 상태 자체는 Temp에 저장하지 않습니다. 결과를 읽는 네트워크가 입력 계산·타이머 호출 뒤에 위치하는지 확인합니다.
9

가상 시간 실습 — 2초 TON을 천천히 관찰

이 모형은 브라우저의 실제 시계나 PLC 타이머를 쓰지 않습니다. “조건 평가”로 입력 변화를 가상 스캔에 반영하고, “시간 진행” 버튼으로 일정한 가상 시간만 증가시킵니다.

조건을 설정하고 평가하거나 시간을 진행하세요.

가상 시간 0ms / PT=2000ms IN=FALSE / ET=0ms / Q=FALSE / Lamp=FALSE

    입력만 바꾸면 마지막 계산 결과가 유지됩니다. 조건 평가 또는 시간 진행 때 갱신합니다. IN이 FALSE→TRUE로 처음 평가되는 시점이 가상 타이머 시작점이고, 해당 시작 평가에는 경과 시간을 누적하지 않습니다. IN이 계속 TRUE인 뒤의 시간 진행부터 ET가 증가합니다.

    이 모형의 ET는 2000ms에서 포화합니다. 실제 CPU의 정확한 타이머 내부 표현·분해능·스캔 시점·오차를 재현하거나 검증하는 도구가 아닙니다.

    시험표 — 유지·해제·Reset·두 인스턴스

    시험조작예상 결과
    시작 준비초기화 후 Enable=TRUE, Sensor=TRUE, 조건 평가IN TRUE, ET=0, Q FALSE
    1.5초 경과+500ms 세 번ET=1500ms, Lamp FALSE
    2초 도달+500ms 한 번 추가ET=2000ms, Lamp TRUE
    계속 감지추가 +500msLamp TRUE 유지, ET 포화
    센서 해제Sensor=FALSE, 조건 평가ET=0, Q·Lamp FALSE
    재감지Sensor=TRUE, 조건 평가 후 +500msET=500ms, 아직 FALSE
    ResetReset=TRUE, 조건 평가IN FALSE, ET=0
    허가 해제Reset FALSE, Enable FALSE, 조건 평가초기화 상태 유지

    두 인스턴스 비교

    TIA Portal 선택 실습에서는 같은 FB를 DB_DelayA와 DB_DelayB로 각각 호출하고 SensorA·SensorB를 별도로 연결합니다. A를 먼저 켜고 1초 뒤 B를 켜면 각각 자신의 시작점에서 약 2초 후 LampA·LampB가 켜지는지 확인합니다.

    사람의 클릭 간격을 정밀한 PLC 시간 시험으로 간주하지 않습니다. 실제 시뮬레이션 결과는 호출 주기·감시 화면 갱신·입력 변경 시점과 함께 기록합니다. 자동 시험 신호는 실제 출력과 연결하지 않습니다.
    11

    실습 확장 — 시간·유효성·최종 출력 분리

    한 단계씩 확장하되 요구사항과 시험표를 먼저 수정합니다.

    1. PT를 Time 입력 DelayTime으로 바꾸고 허용 범위와 운전 중 변경 정책을 정의합니다.
    2. Sensor가 꺼져도 완료를 유지하고 싶다면 별도 DoneMemory와 Reset 우선순위를 설계합니다. TON.Q와 저장된 완료를 다른 태그로 둡니다.
    3. 가상 아날로그 값이 유효하고 설정 범위 이상일 때만 타이머를 시작하도록 비교 블록을 추가합니다.
    4. 설정 오류·센서 무효 시 Lamp·진단·경과값의 의미를 문서화합니다.
    5. 같은 최종 출력에 여러 블록이 쓰지 않도록 최종 출력 결정 위치를 정합니다.
    입력 품질→조건 비교→시간 검증→필요한 상태 저장→최종 표시

    블록 수가 늘었다고 기능이 더 안전해지는 것은 아닙니다. 입력 품질과 실패 상태의 정책, 호출 순서·인스턴스 구분이 함께 있어야 합니다.

    12

    문제 해결과 디버깅 관찰값

    증상확인할 내용
    블록이 연결되지 않음입력·출력 방향과 자료형 호환성
    타이머가 계속 0TimerIn·Reset·Enable·인스턴스·호출 확인
    타이머가 초기화되지 않음FALSE에서도 실제 호출되는지·인스턴스 공유 여부
    A/B 타이머가 서로 간섭같은 인스턴스 DB 또는 멀티인스턴스 재사용 여부
    측정 계산이 이전 값 유지EN=FALSE의 결과 처리·Valid·기본값
    수치의 소수부 손실정수 나눗셈·변환 위치
    표시가 한 호출 늦음결과 참조와 블록 실행의 네트워크 순서
    ENO가 FALSE명령별 실패 조건·입력 범위·EN 상태

    관찰 태그: Enable, Sensor, Reset, TimerIn, DelayTimer.Q, DelayTimer.ET, Lamp, Elapsed. 외부에서 타이머 내부 데이터를 덮어쓰지 말고 정상 입력·호출 상태부터 확인합니다.

    EN/ENO 상태는 실제 기계 피드백이 아닙니다. 명령의 계산 성공과 장치의 물리적 동작 성공을 구분합니다.

    확인 문제와 제출 과제

    1. FBD와 FB는 같은 말인가요?

    아닙니다. FBD는 표현 언어이고 FB는 인스턴스별 상태를 가질 수 있는 기능 구성 단위입니다.

    2. TON.IN=FALSE와 TON 호출 생략은 같은가요?

    아닙니다. FALSE로 호출하면 타이머의 해제·초기화 동작을 평가하지만 호출 생략은 그 평가 자체를 수행하지 않습니다.

    3. 두 독립 센서의 지연에 하나의 타이머 인스턴스를 써도 되나요?

    독립 상태가 필요하므로 별도 인스턴스를 사용해야 합니다.

    4. 센서가 1.5초 켜졌다 꺼지면 2초 TON은 완료되나요?

    일반 TON은 완료되지 않고 IN이 FALSE인 호출에서 초기화됩니다. 재감지하면 다시 시간을 측정합니다.

    5. TON.Q를 완료 이력으로 저장해도 되나요?

    TON.Q 자체는 IN 해제 시 사라지는 결과입니다. 완료 이력 저장이 필요하면 별도 메모리와 해제 정책을 설계합니다.

    6. ENO가 TRUE이면 모터가 회전한 것인가요?

    아닙니다. 일반적으로 명령 실행에 관한 상태이며 실제 운전은 별도 피드백으로 확인합니다.

    실습 제출

    1. 논리·연산·TON 블록의 입력·출력·자료형 표시 도식
    2. 종합 FB 인터페이스와 단일/멀티인스턴스 구분
    3. 정상·해제·Reset·독립 인스턴스 시험표
    4. EN 호출 생략과 IN=FALSE의 차이 설명
    5. 도구 버전·컴파일 결과·미실행 항목과 제한 사항

    6주차 핵심 정리

    • FBD는 기능과 데이터 흐름을 표현하는 언어이며 FB와 다른 개념입니다.
    • 연결선에는 자료형과 실행 의미가 있습니다.
    • EN으로 호출을 생략하는 것과 IN=FALSE로 평가하는 것은 다릅니다.
    • TON은 고유 인스턴스를 사용하고 매 스캔 조건을 평가합니다.
    • 조건 해제·Reset·두 인스턴스 독립성을 함께 시험합니다.
    • 가상 시간 계산은 실제 CPU 타이밍 검증이 아닙니다.

    공식 참고 자료와 검증 범위

    FB·EN/ENO·타이머·멀티인스턴스는 아래 Siemens 공식 자료를 참고했습니다. 문서는 이전 버전 예시를 포함하며 정확한 명령 동작·생성 자료형·지원은 대상 CPU와 설치 버전의 도움말을 확인합니다. 도식·가상 시간 모델·시험표는 본 교안용 구성입니다. 파일 구조·링크·논리 조합·가상 타이머 모델은 점검했으나 실제 TIA Portal 컴파일·PLCSIM 실행·브라우저 렌더링·클릭 자동 시험은 수행하지 않았습니다.
