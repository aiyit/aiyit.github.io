1

IEC 61131-3 — 작성 방식과 의미의 공통 규칙

IEC 61131-3은 PLC 프로그래밍 언어의 구문(Syntax)과 의미(Semantics)를 정의하는 국제표준입니다. 어떤 기호와 문장을 사용할 수 있는지뿐 아니라 해당 표현이 무엇을 뜻하는지를 다룹니다.

표준은 공통 기반을 제공하지만 제조사별 도구, 지원 CPU, 라이브러리, 입출력 주소, 프로젝트 구조가 모두 같다는 뜻은 아닙니다. 같은 논리를 다른 도구로 옮길 때도 선언·지원 기능·실행 조건을 검토해야 합니다.

공통 규칙을 배운다 → 제조사의 구현을 확인한다 → 정확한 CPU·버전에서 검증한다
이번 수업은 전체 지도를 익히는 개요입니다. 실제 배선·PLC 다운로드·출력 조작은 하지 않습니다. 예제의 Permit은 일반 가상 실행 허가이며 안전 기능이 아닙니다.
2

판본 구분 — 기존의 다섯 가지 분류와 2025판

오래된 교재에서 “PLC 언어 다섯 가지”로 LD·FBD·ST·IL·SFC를 함께 소개하는 경우가 있습니다. 판본과 분류 방식을 구분하면 혼동을 줄일 수 있습니다.

자료·판본공식 소개의 구성학습 시 해석
IEC 61131-3:2013, 제3판문자 언어 IL·ST와 그래픽 언어 LD·FBD, 순서 구조를 위한 SFC 요소기존 교재와 설치된 시스템을 읽는 데 필요한 배경
IEC 61131-3:2025, 제4판문자 언어 ST, 그래픽 언어 LD·FBD, 추가 구조화 요소 SFC현재 판의 언어 목록과 SFC의 구조화 역할을 구분
제조사 도구지원 언어·명칭·확장 기능은 제품과 버전에 따라 달라짐표준판과 제품 지원판을 동일시하지 않음

IEC 공식 소개에 따르면 제4판은 2025년 5월 22일 발행되었습니다. 이 판의 언어 묶음에는 IL이 포함되어 있지 않습니다. 상세 추가·삭제·폐기 항목은 표준의 Annex B에서 구분하므로 이 교안은 모든 변경점을 나열하거나 과거 코드를 자동으로 무효라고 판단하지 않습니다.

표준의 새 판이 나왔다고 설치된 PLC나 TIA Portal이 그 기능을 모두 지원하거나 기존 언어를 즉시 사용할 수 없게 되는 것은 아닙니다. 대상 제품의 문서와 프로젝트 조건을 확인합니다.
3

전체 지도 — LD · FBD · ST · SFC · IL

항목표현이번 수업의 초점
LD, Ladder Diagram접점·코일과 연결선Bool 조건의 시각화
FBD, Function Block Diagram기능 블록과 신호 연결논리·연산·기능 호출의 흐름
ST, Structured Text문자 기반 구조화 문장조건·반복·계산·배열 처리
SFC, Sequential Function Chart단계·전이·동작프로그램·FB 내부의 순서 구조화
IL, Instruction List명령어 목록 형태의 기존 문자 표현이전 판·레거시 자료의 배경 설명

특정 표현이 늘 우월한 것은 아닙니다. 조건 논리를 읽기 쉽게 표현하는 일, 계산 데이터를 다루는 일, 공정 단계를 표현하는 일은 서로 다른 요구입니다. 하나의 프로젝트에서 역할에 따라 여러 언어로 작성된 블록을 함께 사용할 수도 있습니다.

언어 선택의 기준: 작업의 성격 + 팀의 유지보수 역량 + 실제 CPU·도구의 지원 범위

표준 명칭과 Siemens 명칭 대응

표준·개념Siemens에서 만나는 이름주의점
LDLAD, Ladder Logic독일어 자료에는 KOP 표기도 존재
FBDFBD, Function Block Diagram독일어 자료에는 FUP 표기도 존재
STSCL, Structured Control LanguageST 계열 구현이며 제조사 문법·확장 확인
SFC 구조GRAPH / S7-GRAPH표준 구조와 편집기·실행 환경을 구분
기존 명령어 목록 계열STL / AWL표준 IL과 도구의 명령을 완전히 같은 언어로 단정하지 않음

Siemens의 IEC 61131-3 제3판 준수 문서는 STEP 7의 명칭과 구현 기능을 대응해 설명합니다. 이 자료는 2015년 문서이므로 제4판의 전 기능 지원 증명이나 모든 CPU의 지원표로 쓰면 안 됩니다.

S7-1200·S7-1500의 언어 지원과 GRAPH 사용 가능 여부는 정확한 CPU, STEP 7 패키지·라이선스, 버전 조건으로 확인합니다. 메뉴 이름을 안다고 모든 장치에서 사용할 수 있는 것은 아닙니다.
5

공통 요구사항 — 세 가지 표현으로 비교할 준비

다음과 같은 기억 없는 가상 표시 로직을 LD·FBD·SCL로 표현합니다.

“일반 실행 허가가 있고, A 또는 B 중 하나 이상이 TRUE이면 램프를 켠다.”
태그자료형·구분의미
A, BBool, Input가상 조작 신호
PermitBool, Input일반 표시 허가
LampBool, Output표시 결과
Lamp = Permit AND (A OR B)

위 수식은 논리 관계를 보여 주는 수학적 표기입니다. 실제 SCL 대입은 다음 예제처럼 :=를 사용합니다. 괄호는 A·B의 OR를 먼저 묶어 의도를 명확하게 합니다.

입력이 FALSE인 경로도 출력 결과를 정의합니다. “조건이 참일 때만 TRUE를 쓰고 나머지 때는 아무것도 하지 않는 코드”는 이전 값이 남아 요구사항과 달라질 수 있습니다.
6

LD/LAD — 접점과 코일로 읽기

개념도: 접점은 태그의 논리값 검사, 코일은 결과 대입

|----[ Permit ]----+----[ A ]----+----( Lamp )----|
|                  |             |
|                  +----[ B ]----+

Permit과 (A 또는 B)가 모두 참이면 Lamp = TRUE

직렬 접점은 AND, 병렬 경로는 OR를 표현하는 데 사용할 수 있습니다. LD의 접점은 물리 스위치를 그대로 그린 배선도가 아니라 태그 상태를 검사하는 프로그램 요소입니다.

LD 요소읽는 방법
정상 열림형 논리 접점 [ ]대상 Bool이 TRUE이면 논리 경로 통과
부정형 논리 접점 [/ ]대상 Bool이 FALSE이면 논리 경로 통과
일반 코일 ( )해당 논리 결과를 Bool 변수에 대입
물리 접점 NO/NC와 프로그램의 정상/부정 논리 접점을 혼동하지 마세요. 물리 배선으로 만들어진 입력값을 프로그램에서 다시 검사합니다. 그림은 학습용 문자 도식이며 가져오기 가능한 LAD 파일이 아닙니다.

다음 5주차에는 자기유지·우선순위·인터록 등 상태가 있는 로직을 자세히 다룹니다.

7

FBD — 블록 연결로 조건과 데이터 흐름 표현

학습용 개념도

A -------+
         [ OR ]----+
B -------+        |
                  [ AND ]---- Lamp
Permit -----------+

OR 출력과 Permit을 AND 블록의 입력으로 사용

FBD는 논리·계산·변환·타이머 같은 기능을 블록으로 표현하고 입출력을 연결합니다. 블록의 이름, 파라미터 자료형, 신호의 연결 관계를 함께 읽습니다.

그림의 연결선만 보고 모든 블록이 물리적으로 동시에 실행된다고 가정하면 안 됩니다. 실제 실행 순서·피드백·호출 규칙은 편집기와 프로그램의 의미에 따라 확인합니다.

FBD라는 언어와 FB라는 프로그램 구성 단위는 다릅니다. FBD로 FB를 작성할 수 있지만, SCL로도 FB를 작성할 수 있습니다.

다음 6주차에는 블록 호출과 변수·타이머·연산을 연결하는 실습으로 확장합니다.

8

ST/SCL — 조건과 계산을 문자로 표현

다음은 TIA Portal SCL 블록 본문용 예시입니다. A·B·Permit은 Bool Input, Lamp는 Bool Output으로 먼저 선언합니다. #은 이 예제에서 블록 지역 태그를 나타내는 Siemens 표기입니다.

// 같은 논리를 한 줄로 표현
#Lamp := #Permit AND (#A OR #B);

IF 문으로 작성해도 요구사항이 같다면 결과를 일치시킬 수 있습니다.

IF #Permit AND (#A OR #B) THEN
    #Lamp := TRUE;
ELSE
    #Lamp := FALSE;
END_IF;
구문의미
:=오른쪽 결과를 왼쪽 변수에 대입
=두 값이 같은지 비교
;문장 종료
IF ... THEN ... ELSE ... END_IF조건에 따라 실행할 구간 선택
이 예제는 블록 본문이며 완전한 프로젝트·변수 선언 파일이 아닙니다. 지역 태그 구문과 선언 방법은 도구별로 다릅니다. 문자 언어가 항상 더 빠른 실행을 보장하는 것도 아닙니다.

다음 7주차에서는 자료형·제어문·반복문·배열 처리를 자세히 학습합니다.

9

SFC — 같은 논리의 그림이 아니라 단계 구조

SFC는 단계와 전이로 동작 순서를 조직합니다. 앞의 기억 없는 램프 식과는 다른 종류의 예제로, “시작 → 작업 → 완료”라는 기억 있는 순서를 살펴봅니다.

S0 · 대기 / 작업 명령 OFF
↓ StartEdge AND Ready
S10 · 작업 / 작업 명령 ON
↓ WorkDone
S20 · 완료 / 완료 표시 ON
↓ Reset → S0
요소역할
Step현재 활성 상태
Transition다음 단계로 이동할 조건
Action단계와 연결된 실행 처리
Initial step초기화 시 시작 단계
SFC 도식의 동작을 실행할 때는 단계·전이 평가 순서, 동작의 저장/비저장 성격, 초기화·고장·재시작 정책이 필요합니다. 단순히 그림을 그렸다고 실제 I/O나 안전 제어가 완성되는 것은 아닙니다.

다음 8주차에서는 직렬·선택·병렬 순서와 GRAPH 및 SCL 대체 구현을 다룹니다.

10

POU·Function·FB와 Siemens OB·FC·DB

프로그램 구성 단위(POU)는 코드를 기능별로 조직하는 개념입니다. 언어는 “어떻게 표현하는가”, 구성 단위는 “어떤 역할로 나누고 호출하는가”에 관한 질문입니다.

표준의 기본 개념학습할 의미
Program실행할 프로그램의 구성 단위
Function입력에 따른 계산·처리의 재사용 단위
Function Block인스턴스별 상태를 가질 수 있는 재사용 단위
Siemens 요소주요 역할혼동 방지
OB주기·시작·이벤트 등 운영체제의 진입점표준 Program과 단순한 일대일 이름 치환은 아님
FC함수 형태의 처리·계산인스턴스 DB가 필요한 FB와 구분
FB호출 사이 상태를 가진 기능 구성인스턴스마다 상태를 독립적으로 보관
DB전역 데이터 또는 FB 인스턴스 데이터코드를 표현하는 언어가 아님
인스턴스는 같은 FB 형식으로 만든 개별 상태 공간입니다. 장치 두 대를 같은 FB로 제어하더라도 서로 다른 인스턴스가 필요할 수 있습니다.

FB의 Static 상태가 호출 사이 유지된다는 것과 전원 차단 후 데이터가 유지된다는 것은 다릅니다. Retain·초기화·재시작은 별도 설정과 설계 사항입니다.

어떤 언어든 값을 읽기 전에 정의하고, 출력은 의도한 모든 경로에서 결정하며, 같은 출력에 여러 곳에서 쓰지 않도록 설계합니다. 타이머·카운터의 상태와 호출 조건도 중요합니다.

그림으로 그렸다고 실제 입력을 계속 새로 읽거나, 문자로 썼다고 한 번만 실행하는 것이 아닙니다. PLC의 호출·스캔·이벤트·I/O 갱신 규칙이 프로그램 실행을 결정합니다.

다른 언어로 옮긴 뒤에는 논리식뿐 아니라 상태 유지, 평가 순서, 자료형, 에지·시간 동작을 검증해야 합니다.

12

가상 비교 실습 — LD·FBD·SCL 결과 맞추기

세 Bool 입력을 전환하면서 앞의 공통 논리식 결과를 확인합니다. 브라우저에서 동일 논리를 세 방식으로 계산한 교육용 모델이며 실제 LD/FBD/SCL 실행 엔진이 아닙니다.

LD 개념 결과: FALSE FBD 개념 결과: FALSE SCL 개념 결과: FALSE 일치 여부: 일치

상태·스캔·실행 시간·PLC I/O·언어 구문 분석은 재현하지 않습니다. 실제 언어 변환 정확성을 검증하는 도구가 아닙니다.

FALSEFALSETRUEFALSE

FALSETRUETRUEFALSE

실습 순서

  1. Permit=FALSE인 네 조합에서 Lamp가 항상 FALSE인지 확인합니다.
  2. Permit=TRUE인 상태에서 A·B를 바꾸어 OR 결과를 확인합니다.
  3. LD에서 직렬·병렬 경로를, FBD에서 OR→AND 연결을 찾아 표시합니다.
  4. SCL의 괄호를 제거하거나 AND/OR를 바꾸면 어떤 요구사항이 달라지는지 설명합니다. 실행 전에 진리표로 검토합니다.

언어 선택과 이식성 체크리스트

요구사항 예시검토할 표현선택 근거
여러 Bool 허가·인터록LD/LAD 또는 FBD조건과 경로를 시각적으로 읽기
계산·배열·반복ST/SCL식과 자료구조 처리 명확화
단계·전이·순서SFC 구조·지원 GRAPH 환경현재 단계와 이동 조건 분리
기존 설치 코드 분석해당 장치의 기존 언어지원 도구·문서·팀 역량 우선

언어와 프로젝트 교환 형식은 다릅니다. IEC 61131-10은 XML 기반 교환 형식을 다루지만, 파일을 교환할 수 있다는 사실만으로 모든 도구·하드웨어 사이에서 동일 동작이 보장되는 것은 아닙니다.

  • 자료형·주소·스코프·라이브러리가 호환되는가?
  • 타이머·카운터·이벤트·순서 실행 의미가 같은가?
  • 하드웨어 I/O·통신·기술 객체가 이전 가능한가?
  • 보호 설정·라이선스·언어 지원이 맞는가?
  • 정상·고장·경계·재시작 시험 계획이 있는가?
자동 변환이나 복사 성공은 동작 검증을 대신하지 않습니다. 요구사항·자료형·실행·I/O까지 확인합니다.
14

확인 문제와 제출 과제

1. IEC 61131-3은 무엇을 정의하나요?

PLC 프로그래밍 언어의 구문과 의미, 프로그램 구조화 등에 관한 공통 규칙을 정의합니다. 제조사의 전체 엔지니어링 환경이 모두 같다는 뜻은 아닙니다.

2. 2025판도 IL을 언어 묶음에 포함하나요?

IEC 공식 소개의 제4판 묶음에는 ST·LD·FBD가 있고 SFC는 추가 구조화 요소로 설명됩니다. IL은 그 묶음에 포함되지 않습니다. 기존 시스템의 지원 여부는 제품 문서로 별도 확인합니다.

3. SCL과 ST는 어떤 관계인가요?

SCL은 Siemens의 ST 계열 언어 명칭입니다. 문법 세부·확장·지원 범위가 모든 제조사 ST와 완전히 같다고 가정하지 않습니다.

4. FBD와 FB는 같은 뜻인가요?

아닙니다. FBD는 표현 언어, FB는 상태를 가진 기능 구성 단위입니다. SCL로도 FB를 작성할 수 있습니다.

5. 공통 예제에서 Permit=FALSE, A=TRUE, B=TRUE이면?

Lamp는 FALSE입니다. A OR B가 TRUE여도 Permit과의 AND 조건을 만족하지 않습니다.

6. LD 접점은 실제 물리 NO/NC 접점과 같은 것인가요?

아닙니다. 프로그램 접점은 태그의 논리값을 검사하는 요소이고, 물리 접점·배선으로 만들어진 입력값과 구분합니다.

제출 과제

  1. 표준 명칭·Siemens 명칭 대응표
  2. 공통 램프 논리를 LD 개념도·FBD 개념도·SCL로 표현
  3. 여덟 입력 조합의 예상값과 관찰값 기록
  4. 기억 없는 논리와 단계 제어가 다른 이유 설명
  5. 이식·변환 시 확인할 사항 세 가지와 미확인 사항 기록

다음 주: 래더 다이어그램(LD) 심화

접점·코일의 기본 읽기를 바탕으로 자기유지, 정지 우선, 에지·인터록을 학습합니다. 실제 장치 출력이 아닌 가상 입력과 내부 태그로 동작을 검토합니다.

4주차 핵심 정리

  • IEC 61131-3은 언어의 구문·의미·구조화 규칙을 다룹니다.
  • 2025판은 ST·LD·FBD와 추가 구조화 요소 SFC를 설명하며 과거 분류와 구분합니다.
  • SCL·GRAPH 등 제조사 명칭과 표준 개념을 구분합니다.
  • LD·FBD·SCL은 같은 조합 논리를 서로 다르게 표현할 수 있습니다.
  • SFC는 현재 단계와 이동 조건을 조직하는 구조입니다.
  • 언어 선택·변환 후에도 지원 조건·상태·자료형·실행을 검증합니다.

공식 참고 자료와 적용 범위

판본 설명은 IEC 공식 공개 소개를, Siemens 명칭·구현 설명은 제3판 기준의 2015년 준수 문서를 참고했습니다. IEC 표준 전문의 모든 조항을 검토하거나 특정 CPU의 제4판 전 기능 지원을 인증한 자료가 아닙니다. 개념도·예제·가상 실습은 본 교안용 구성입니다. 파일 구조·링크와 여덟 조합의 논리 일치는 점검했으나 TIA Portal 컴파일·실물 PLC·브라우저 렌더링·클릭 자동 시험은 수행하지 않았습니다.
