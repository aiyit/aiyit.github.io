9주차 · Module 09

TIA Portal 프로젝트 생성 및 하드웨어 구성

CPU·모듈·네트워크·I/O 주소를 실제 장비와 일치시킨다

오늘의 학습 목표

  • TIA Portal에서 새 프로젝트를 만들고 화면 구조를 설명할 수 있다.
  • 주문번호와 펌웨어를 확인해 CPU·모듈을 구성할 수 있다.
  • IP 계획과 I/O 주소를 확인하고 PLC 태그를 작성할 수 있다.
  • 컴파일·온라인 검색·다운로드의 차이와 영향 범위를 구분할 수 있다.
  • 프로젝트를 검증하고 복구 가능한 형태로 보관할 수 있다.

선수학습: PLC 하드웨어, 디지털·아날로그 I/O, 기초 프로그램 / 기본 범위: S7-1200·S7-1500 프로젝트 구성 / 안전 설정·실제 설비 시운전은 제외

1

오늘의 결과물과 작업 순서

이번 주에는 프로그램을 작성하기 전에 PLC의 실제 구성을 TIA Portal 프로젝트에 정확하게 반영하는 방법을 배웁니다. CPU와 모듈이 맞아야 입출력 주소, 통신 설정, 진단 정보도 올바르게 연결됩니다.

프로젝트 생성→CPU 선택→모듈 구성→네트워크·주소 설정→컴파일→검증·보관
  • CPU와 모듈 구성이 기록된 실습 프로젝트
  • IP 주소 계획표와 I/O 태그 목록
  • 컴파일 결과 및 실습 점검표
  • 복구 가능한 프로젝트 아카이브
이 HTML은 교안입니다. 실행 가능한 TIA Portal 프로젝트나 장치 설정 파일이 아닙니다. 화면 이름은 설치 버전에 따라 달라질 수 있으며, 특정 CPU 주문번호·펌웨어는 사용자가 가진 장비를 기준으로 선택합니다.

새 프로젝트 만들기 — 이름과 저장 규칙

  1. TIA Portal을 실행하고 Create new project(새 프로젝트 생성)를 선택합니다.

CPU 추가 — 제품명만 보고 선택하지 않기

  1. Add new device(새 장치 추가)를 선택합니다.
  2. Controllers에서 실제 CPU 제품군을 찾습니다.
  3. 명판에 적힌 주문번호와 카탈로그 항목을 대조합니다.
  4. 실제 펌웨어와 해당 TIA Portal의 지원·호환 조건을 확인합니다.
  5. 장치 이름을 입력하고 Device view를 엽니다.
확인 순서확인 이유

카탈로그에서 선택하는 장치 버전은 실제 CPU 펌웨어를 자동으로 업데이트하는 기능이 아닙니다. 펌웨어 변경은 별도의 승인된 작업입니다.

IP 주소 계획 — PC와 PLC를 구분하기

아래는 외부 네트워크와 분리된 교육망을 가정한 예시입니다. 실제 주소를 정할 때는 관리자에게 할당받은 범위를 사용하고 중복 여부를 확인합니다.

항목실습용 예시설명
서브넷192.168.10.0/24교육용 예시 범위
PC 유선 어댑터192.168.10.10PLC와 통신할 PC의 주소
PLC 인터페이스192.168.10.20대상 PLC 포트의 주소
서브넷 마스크255.255.255.0이 예시의 PC·PLC에 동일 적용
기본 게이트웨이외부 라우팅이 없다면 미설정기관의 네트워크 정책을 우선

이 예시에서는 PC와 PLC의 앞 세 옥텟이 같고 마지막 값은 달라야 합니다. 이는 /24 마스크인 이 예시에 해당하며 모든 서브넷에 일반화하면 안 됩니다. 192.168.10.0은 네트워크 주소, 192.168.10.255는 이 서브넷의 브로드캐스트 주소이므로 장치에 할당하지 않습니다.

PC · .10↔분리된 교육망↔PLC · .20
PC와 PLC에 같은 IP를 넣지 마세요. Wi-Fi, VPN, 가상 어댑터가 여러 개일 때는 PLC 케이블이 연결된 실제 어댑터를 선택합니다. 보안 기능을 무조건 끄는 방법으로 해결하지 않습니다.

프로젝트의 통신 설정과 실제 장치 설정

  1. CPU의 해당 PROFINET/Ethernet 인터페이스를 선택합니다.
  2. Properties에서 Ethernet addresses 또는 이에 해당하는 항목을 엽니다.
  3. 프로젝트의 IP 주소와 서브넷 마스크를 입력합니다.
  4. 필요하면 새 서브넷을 만들고 인터페이스를 연결합니다.
  5. PROFINET 장치 이름을 사용하는 구성에서는 이름과 I/O 시스템 할당도 확인합니다.
작업변경 위치의미
오프라인 IP 입력프로젝트의도하는 장치 설정을 기록
실제 IP 지정물리 장치온라인 장치의 주소에 영향
장치 이름 지정물리 장치PROFINET 식별에 영향
다운로드프로젝트 → PLC선택한 구성·프로그램을 장치에 반영
프로젝트에서 IP를 바꾸었다고 실제 PLC의 IP가 즉시 바뀌는 것은 아닙니다. 반대로 온라인에서만 장치 주소를 바꾸면 오프라인 프로젝트와 불일치할 수 있습니다.

IP 주소, MAC 주소, PROFINET 장치 이름은 서로 다른 식별 정보입니다. 실제 장치를 선택할 때는 명판·MAC 주소·주문번호·물리적 연결을 함께 대조하세요. 별도 IP 지정과 다운로드의 구체적인 동작은 CPU 상태와 설정 방식에 따라 다를 수 있습니다.

I/O 주소와 PLC 태그 — 채널을 이름에 연결하기

모듈의 I/O addresses에서 실제 할당된 주소를 확인한 다음 PLC tag table을 작성합니다. 아래 주소는 학습용 가정이며 자동 할당 결과와 다를 수 있습니다.

태그명자료형예시 주소의미
StartPBBool%I0.0시작 버튼 입력
StopOKBool%I0.1TRUE이면 정지 조건 해제라는 실습 약속
PartSensorBool%I0.2제품 감지 입력
RunLampBool%Q0.0운전 표시등 출력
RawAnalogInt%IW64아날로그 원시값 예시
표기읽는 방법주의점
%I0.0입력 바이트 0의 비트 0해당 주소가 실제 채널인지 확인
%Q0.0출력 바이트 0의 비트 0실제 부하와 연결 여부 확인
%IW64입력 워드, 시작 바이트 642바이트를 사용하므로 다음 바이트와 중첩 주의
아날로그 원시값의 범위·부호·상태값은 모듈과 측정 범위에 따라 다릅니다. %IW64라는 주소만 보고 측정 범위가 정해지는 것은 아닙니다. StopOK라는 이름도 실제 NC/NO 배선과 프로그램의 논리 약속을 확인해야 합니다.

실습용 DB 태그는 하드웨어 입력 주소가 아닙니다. 실제 센서 대신 시뮬레이션할 때는 물리 I/O 태그와 내부 DB 태그를 구분합니다.

저장과 컴파일 — 오류부터 해결하기

  1. 프로젝트를 저장합니다.
  2. CPU를 선택하고 하드웨어 컴파일을 실행합니다.
  3. 프로그램을 추가했다면 소프트웨어도 컴파일합니다.
  4. 결과 창의 오류와 경고를 펼쳐 원인과 위치를 확인합니다.
  5. 수정 후 다시 컴파일하고 검증 결과를 기록합니다.
메시지 유형대표 원인대응
하드웨어 구성 오류허용되지 않은 슬롯·모듈 조합정확한 카탈로그와 장착 규칙 확인
주소 충돌I/O 주소 영역 중첩시작 주소와 점유 길이 확인
버전/지원 문제선택 장치와 설치 지원 불일치호환성·HSP·업데이트 확인
프로그램 오류미선언 태그·자료형 불일치태그·블록 인터페이스 수정
경고미연결·기본 설정·검토 필요 항목 등내용을 읽고 수용 근거 기록
컴파일 성공은 구성의 정적 검사가 통과했다는 뜻입니다. 실제 배선, 통신 도달성, 장치의 안전한 동작까지 입증하는 것은 아닙니다.
11

온라인 검색과 하드웨어 감지

실물 교육 장치를 사용할 때만 수행합니다. 오프라인 구성 실습이라면 이 절차는 설명으로 대체합니다.

  1. 승인된 교육용 PLC에 케이블을 연결하고 사용 어댑터를 확인합니다.
  2. Online access 또는 Accessible devices에 해당하는 장치 검색 기능을 엽니다.
  3. PN/IE와 실제 유선 네트워크 어댑터를 선택합니다.
  4. 목록의 CPU를 주문번호·MAC 주소 등으로 대조합니다.
  5. CPU 정보를 읽어 오프라인 CPU 및 모듈 목록과 비교합니다.

미지정 CPU에서 감지하는 방식

지원되는 환경에서는 Unspecified CPU를 추가한 뒤 Detect로 실제 CPU와 연결 모듈을 감지할 수 있습니다. 감지 후에도 모듈 파라미터, 주소, 네트워크와 프로그램의 적합성을 검토해야 합니다.

검색·감지와 다운로드는 다릅니다. 검색 결과에서 이름이 비슷하다는 이유로 선택하지 마세요. 네트워크에 보이는 장치라는 사실이 변경 권한을 뜻하지도 않습니다.

동일 링크의 장치 검색과 IP 기반 통신은 조건이 다를 수 있습니다. 장치가 목록에 보인다는 사실만으로 IP 설정이 완전하다고 판단하지 않습니다.

다운로드 전 확인 — 실습 장치만 사용

다운로드는 프로젝트 내용을 PLC로 전송하는 작업이고, 업로드는 PLC의 내용을 PC 쪽으로 가져오는 작업입니다. 초보자는 방향을 먼저 확인해야 합니다.

  1. 대상 CPU와 전송 인터페이스를 선택합니다.
  2. 다운로드 미리보기에서 변경 내역과 요구 조치를 확인합니다.
  3. 예상 밖의 장치, 삭제·초기화·STOP 요구가 있으면 취소하고 확인합니다.
  4. 승인 범위 내에서만 전송하고, 전송 후 진단과 온라인/오프라인 차이를 확인합니다.
  5. RUN 전환은 실습 안전 조건을 확인한 뒤 별도 판단합니다.
과거 교육 문서에 나오는 “모두 덮어쓰기”나 “Start all”을 그대로 따라 누르지 마세요. 현재 장치와 버전의 미리보기를 읽고, 부하가 움직일 수 있는 RUN 전환을 자동 절차로 취급하지 않습니다.

문제 해결 — 장치가 보이지 않거나 구성이 다른 경우

증상우선 점검피해야 할 대응
장치 검색 결과가 없음전원·링크 LED·케이블·선택 어댑터·분리망 구성생산망에 무작정 연결
검색되지만 접속 실패PC/PLC IP·마스크·중복·접근 보호·네트워크 정책방화벽·보호 기능 일괄 해제
다른 CPU가 선택됨MAC·주문번호·장치 연결 위치이름만 보고 다운로드
모듈 불일치실물 슬롯·주문번호·펌웨어·오프라인 구성비슷한 모듈로 임의 대체
I/O가 예상대로 안 보임시작 주소·채널 상태·전원·배선·프로세스 이미지 할당출력 강제부터 수행
다운로드 미리보기에서 예상 밖 변경현재 CPU 내용과 프로젝트의 차이·백업모두 덮어쓰기 강행
프로젝트가 열리지 않음작성 버전·필요 옵션·보관본 상태원본을 보관하지 않고 변환
점검 순서: 물리 연결 → 장치 식별 → 어댑터와 IP → 프로젝트 일치 → 접근 보호 → 진단 메시지. 오류 문구를 기록하고 원인별로 하나씩 확인합니다.

1. 프로젝트에 IP를 입력하면 실제 PLC도 즉시 바뀌나요?

아닙니다. 오프라인 구성 변경과 실제 장치 설정 반영은 다릅니다. 승인된 주소 지정·다운로드 등 해당 작업이 필요합니다.

2. CPU를 고를 때 제품명 외에 무엇을 확인하나요?

정확한 주문번호, 실제 펌웨어, 프로젝트 장치 버전과 TIA Portal의 지원·호환성을 확인합니다.

3. PC와 PLC의 IP를 같게 해야 하나요?

아닙니다. 같은 /24 예시 서브넷에 속하되 장치별 IP는 달라야 합니다. 중복 주소를 사용하지 않습니다.

4. 컴파일 오류 0개면 실제 출력 시험도 끝났나요?

아닙니다. 실제 배선·통신·장치 동작은 별도의 검증이 필요합니다.

5. %IW64는 64번 비트인가요?

아닙니다. 입력 영역의 바이트 64에서 시작하는 워드 주소입니다. 2바이트를 점유합니다.

제출 과제

  1. CPU와 모듈 배치가 보이는 Device view를 기록합니다.
  2. IP 계획표와 5개 이상의 I/O 태그 표를 작성합니다.
  3. 컴파일 결과와 경고 검토 근거를 남깁니다.
  4. 내부 DB 진리표 시험 결과 또는 오프라인 검증 한계를 적습니다.
  5. 저장·Archive 기능으로 보관하고, 다른 위치에서 복원 가능한지 확인합니다. 아카이브 확장자는 버전에 따라 달라집니다.

9주차 핵심 정리

  • CPU·모듈은 제품명뿐 아니라 주문번호와 버전까지 대조합니다.
  • 프로젝트 설정과 실제 장치 상태는 같다고 가정하지 않습니다.
  • PC와 PLC는 중복되지 않는 주소를 사용하고 서브넷을 확인합니다.
  • I/O 주소는 할당 결과를 기준으로 태그에 연결합니다.
  • 저장 → 컴파일 → 대상 확인 → 승인된 검증 → 아카이브 순서로 작업합니다.
  • 다운로드와 RUN 전환은 실제 장치에 영향을 주는 별도 판단 사항입니다.
