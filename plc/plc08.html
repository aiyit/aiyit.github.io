1

SFC란? — 순서를 단계와 조건으로 표현하기

SFC(Sequential Function Chart, 순차 기능 차트)는 공정의 실행 순서를 단계(Step), 전이(Transition), 동작(Action)으로 표현하는 구조입니다. 무엇을 수행하는 상태인지와 언제 다음 상태로 넘어가는지를 분리하여 복잡한 순서를 읽기 쉽게 만듭니다.

7주차에 배운 CASE 기반 단계 제어는 SFC로 설계한 순서를 코드로 구현하는 한 가지 방법입니다. SFC 도식과 SCL 코드는 표현 방식이 다르며, 같은 제어 요구사항을 나타낼 수 있습니다.

표현강점이번 수업과의 연결
LD·FBD논리 조건과 입출력 관계를 시각화전이 조건·동작 논리를 구성
SCL계산·조건 분기·데이터 처리SFC 설계의 CASE 구현 실습
SFC단계와 순서·분기 구조를 시각화전체 시퀀스를 먼저 설계
핵심 질문: 지금 어느 단계인가? → 그 단계에서 무엇을 하는가? → 어떤 조건에서 다음 단계로 가는가?

초기 단계는 보통 이중 테두리로 표시합니다. 단계와 전이를 번갈아 배치하고, 단계에는 동작을, 전이에는 TRUE/FALSE가 되는 조건식을 작성합니다.

초기 단계가 활성화되었다고 장치가 자동으로 안전한 원점으로 이동한 것은 아닙니다. 위치 확인, 원점 복귀, 출력의 안전 상태는 별도로 설계해야 합니다.
3

전이가 성립하는 조건과 활성 단계

단순 직렬 시퀀스에서는 현재 단계가 활성이고 그 뒤 전이 조건이 참이면 현재 단계를 비활성화하고 다음 단계를 활성화합니다. 여러 갈래를 합류하는 전이는 필요한 선행 단계의 활성 조건도 충족해야 합니다.

현재 활성 단계전이 조건결과
S0Start=FALSES0 유지
S0Start=TRUE AND Ready=TRUES10으로 이동
S10PositionSensor=FALSES10 유지
S10PositionSensor=TRUES20으로 이동
전이는 “조건이 참이다”만으로 항상 실행되지 않습니다. 그 전이가 현재 활성 경로에서 실행 가능한지도 중요합니다.

같은 스캔에서 여러 전이를 연속 처리하는지, 동작을 언제 평가하는지는 구현 환경의 실행 규칙에 따라 달라질 수 있습니다. 이 교안의 SCL 예제는 CASE 한 번으로 한 스캔에 정상 단계 전이를 최대 한 번 처리합니다.

4

동작의 지속과 저장 — N · S · R

액션 한정자(Action qualifier)는 동작이 언제 시작되고 얼마나 유지되는지를 정합니다. 아래는 대표적인 기본 개념이며, 실제 편집기의 표기와 지원 항목은 확인해야 합니다.

한정자개념주의점
N, 비저장 동작단계가 활성인 동안 동작단계 비활성화 후에는 비저장 동작 해제
S, 저장 설정설정된 동작을 단계 종료 뒤에도 유지어느 단계에서 해제할지 반드시 정의
R, 저장 해제대상 저장 동작을 리셋초기화·고장 복귀 정책과 함께 설계

예를 들어 표시등을 “해당 단계 동안만” 켜려면 N형 개념이 간단합니다. 여러 단계에 걸쳐 유지해야 하는 상태는 S/R형 개념을 검토할 수 있지만 해제 경로가 빠지면 의도치 않게 유지될 수 있습니다.

단계 종료와 출력 OFF를 무조건 같은 의미로 생각하지 마세요. 저장 동작은 남을 수 있으며, 여러 위치에서 같은 출력에 쓰면 충돌도 생깁니다. 실제 출력은 한 곳에서 최종 결정하는 방식이 점검에 유리합니다.
5

직렬 시퀀스 설계 — 이송·작업·완료

교육용 가상 장치의 요구사항입니다. 이송 모터로 제품을 작업 위치까지 이동시키고, 가상의 작업 완료 입력을 확인한 다음 완료 상태를 유지합니다. 실제 위험 동작은 포함하지 않습니다.

  1. 초기에는 대기하며 모든 운전 명령을 끕니다.
  2. 시작 상승 에지가 들어오고 실행 허가가 있으면 이송합니다.
  3. 제품 위치 센서가 감지되면 이송을 멈추고 작업 명령을 켭니다.
  4. 작업 완료의 새로운 상승 에지를 감지하면 완료 표시를 켭니다.
  5. Reset으로 대기로 복귀하며, 자동 재시작하지 않습니다.

StartEdge AND Permit AND NOT AtPosition

MotorCmd=1

전이 우선순위

  1. Reset: 대기 상태로 초기화합니다. Permit이 없으면 고장 상태를 유지합니다.
  2. Permit 상실 또는 이송·작업 중 비정상 완료 입력: 고장으로 이동합니다.
  3. 단계별 타임아웃: 고장으로 이동합니다.
  4. 그 외 정상 전이를 판단합니다.
이 예제는 Permit 상실 후 신호가 복구되어도 자동으로 재개하지 않습니다. 원인을 제거한 후 Reset, 새 Start 입력 순서가 필요합니다. 실제 장치의 정지·복귀 정책은 별도 위험성 평가와 공정 요구사항에 따라 정합니다.
7

선택 분기와 병렬 분기

선택 분기: 조건에 따라 한 경로 선택

제품 종류 A/B에 따라 다른 작업을 수행하는 경우입니다. 조건은 서로 배타적으로 만들고, 둘 다 참이거나 둘 다 거짓일 때의 정책도 정의합니다.

제품 분류
TypeA AND NOT TypeB
A 작업
TypeB AND NOT TypeA
B 작업
합류 후 완료

환경에 따라 우선순위 규칙이 있을 수 있으므로 그림의 좌우 위치만 믿지 말고 명시적인 조건으로 의도를 표현하세요.

병렬 분기: 여러 경로를 함께 활성화

두 개의 독립적인 준비 작업을 함께 시작하고 모두 완료된 후 다음 단계로 진행하는 구조입니다. 분기는 이중선으로 나타내는 경우가 일반적이며, 여기서는 텍스트로 관계를 표시합니다.

공통 시작

══ 병렬 분기 ══

A 준비 → A 완료 대기
B 준비 → B 완료 대기

══ 동기 합류: A와 B 경로의 선행 단계 모두 활성 ══

A_Ready AND B_Ready
공통 다음 작업
선택 분기는 한 경로를 고르는 구조, 병렬 분기는 여러 경로가 활성화되는 구조입니다. 병렬 경로에서 같은 실린더·밸브를 동시에 점유하지 않도록 자원 충돌을 검토하세요.
8

인터록·감시·타임아웃의 차이

구분질문예시
전이 조건다음 단계로 넘어가도 되는가?AtPosition=TRUE
인터록, Interlock이 동작을 실행해도 되는가?실행 허가가 있을 때만 모터 명령
감시, Supervision현재 단계에 이상이 발생했는가?허용 시간 초과 또는 입력 모순

Siemens GRAPH에서 인터록은 연결된 동작의 실행 허가에 영향을 줍니다. 인터록 조건이 불만족이라는 이유만으로 정상 전이가 자동으로 차단된다고 가정하면 안 됩니다. 감시는 조건이 만족되면 고장으로 취급하며 단계 진행을 막는 기능입니다. 구체적인 확인·해제 동작은 설정을 확인해야 합니다.

GRAPH의 인터록은 “조건 TRUE → 허가” 개념, 감시는 “조건 TRUE → 고장” 개념이라는 차이에 주의하세요. 일반 시퀀스 기능과 안전 기능을 혼동하지 마세요.

다음 SCL 예제는 GRAPH의 내장 감시를 그대로 재현하지 않습니다. 교육용으로 타임아웃이 발생하면 별도의 고장 단계 900으로 전이하도록 설계합니다.

9

TIA Portal에서 GRAPH로 구성하는 절차

GRAPH는 Siemens에서 단계·전이 기반 시퀀스를 구성하는 도구입니다. 대상 CPU와 설치된 STEP 7 패키지·라이선스가 GRAPH를 지원하는지 먼저 확인합니다. 아래 실습은 GRAPH 지원 S7-1500 환경을 기준으로 하며, 모든 PLC에서 GRAPH를 쓸 수 있다고 가정하지 않습니다.

  1. 실습 프로젝트에서 CPU와 입출력용 내부 DB 태그를 준비합니다.
  2. GRAPH 언어의 FB를 추가하고 초기 단계 S0를 대기로 정합니다.
  3. 직렬 단계 S10·S20·S30과 각 전이를 추가합니다.
  4. 동작 표에 단계별 명령을 입력하고 비저장/저장 동작을 구분합니다.
  5. 전이 조건을 LAD/FBD 등 지원되는 방식으로 작성합니다.
  6. 인터록과 단계 시간 감시, 고장 확인 정책을 별도로 구성합니다.
  7. GRAPH FB를 주기 프로그램에서 호출하고 인스턴스 DB와 필요한 제어 파라미터를 연결합니다.
  8. 컴파일 후 지원되는 시뮬레이션 환경에서 활성 단계·전이 조건·출력 명령을 함께 관찰합니다.
메뉴·FB 파라미터·지원 기능은 버전에 따라 다릅니다. GRAPH를 사용할 수 없는 실습 환경에서는 다음 CASE 기반 FB로 동일한 직렬 순서의 설계 의도를 연습하세요. 이것은 GRAPH 네이티브 파일이 아닙니다.

SCL 대체 실습 — 인터페이스와 타이머 준비

이 실습은 SFC 설계를 일반 SCL FB로 구현합니다. 아래 태그를 선언하고 FB를 매 스캔 호출합니다. 모든 입출력은 가상 DB 태그로 연결합니다.

구분태그자료형·시작값
InputStart, Reset, Permit, AtPosition, WorkDoneIn각각 Bool
OutputMotorCmd, WorkCmd, Done, Fault각각 Bool
OutputStepNoInt
StaticStateInt, 시작값 0
StaticPrevStart, PrevWorkDone각각 Bool, 시작값 FALSE
StaticMoveTimer, WorkTimerIEC TON 멀티인스턴스
TempStartEdge, WorkDoneEdge각각 Bool

타이머 자료형 이름은 환경에 따라 다를 수 있습니다. SCL 편집기에서 TON 명령을 삽입하고 멀티인스턴스를 선택해 MoveTimer와 WorkTimer를 생성하는 방법을 권장합니다. 생성된 인터페이스와 호출 구문을 확인하세요.

이송 제한 5초, 작업 제한 3초는 학습용 임의 값입니다. 실제 공정의 허용 시간 또는 안전 기준이 아닙니다.

아래 코드는 한 FB 본문에 넣습니다. 타이머를 매 스캔 호출하고, 상태 전이 뒤에 최종 출력을 계산합니다. 상태 변수 State는 기본값 0에서 시작하며, 리테인·재시작 정책은 별도로 검토합니다.

11

SCL 대체 실습 — 단계 제어 전체 코드

// 1. 입력 상승 에지: 매 스캔 갱신
#StartEdge := #Start AND NOT #PrevStart;
#PrevStart := #Start;
#WorkDoneEdge := #WorkDoneIn AND NOT #PrevWorkDone;
#PrevWorkDone := #WorkDoneIn;

// 2. 타이머: 모든 스캔에서 호출
#MoveTimer.TON(IN := (#State = 10) AND #Permit AND NOT #Reset,
               PT := T#5s);
#WorkTimer.TON(IN := (#State = 20) AND #Permit AND NOT #Reset,
               PT := T#3s);

// 3. 초기화/고장 우선 판단
IF #Reset THEN
    IF #Permit THEN
        #State := 0;
    ELSE
        #State := 900;
    END_IF;
ELSIF NOT #Permit THEN
    #State := 900;
ELSE
    CASE #State OF
        0: // 대기: 완료 입력이 해제된 상태에서만 시작
            IF #StartEdge AND NOT #AtPosition AND NOT #WorkDoneIn THEN
                #State := 10;
            END_IF;
        10: // 이송
            IF #WorkDoneIn OR #MoveTimer.Q THEN
                #State := 900;
            ELSIF #AtPosition THEN
                #State := 20;
            END_IF;
        20: // 작업
            IF NOT #AtPosition OR #WorkTimer.Q THEN
                #State := 900;
            ELSIF #WorkDoneEdge THEN
                #State := 30;
            END_IF;
        30: // 완료 상태 유지
            #State := 30;
        900: // 원인 제거 후 Reset 필요
            #State := 900;
        ELSE
            #State := 900;
    END_CASE;
END_IF;

// 4. 최종 출력: 상태 전이 이후 한 곳에서 결정
#MotorCmd := (#State = 10) AND #Permit AND NOT #Reset;
#WorkCmd := (#State = 20) AND #Permit AND NOT #Reset;
#Done := (#State = 30);
#Fault := (#State = 900);
#StepNo := #State;

코드 해석

  • 대기에서 시작할 때 위치 센서와 완료 입력이 모두 FALSE여야 합니다.
  • 이송 중 작업 완료 신호가 들어오면 순서 이상으로 고장 처리합니다.
  • 작업 중 위치 센서가 꺼지면 작업 위치를 벗어난 것으로 보고 고장 처리합니다.
  • 타임아웃과 정상 완료가 같은 스캔에 성립하면 타임아웃을 우선합니다.
  • 고장 상태는 Permit이 복구되어도 유지되며 Reset이 필요합니다.
  • Reset 중에는 타이머 입력도 FALSE가 되어 다음 운전을 준비합니다.
전이 스캔에서 새 단계의 출력은 즉시 계산됩니다. 새 단계의 타이머 입력은 다음 FB 호출부터 TRUE가 되므로 타이머 시작 기준에 최대 한 호출 주기의 차이가 있습니다. 정밀한 시간 요구가 있다면 호출 주기와 평가 순서를 검토하세요.

예제에는 고장 원인별 코드, HMI 조작 권한, 원점 복귀, 수동 운전 및 안전 인증 기능이 없습니다. 실제 설비에 적용하는 완성 프로그램이 아닙니다.

확인 문제와 확장 과제

1. 단계, 전이, 동작을 한 문장씩 설명하세요.

단계는 현재 실행 상태, 전이는 다음 단계로 이동하기 위한 논리 조건, 동작은 활성 단계와 연결된 처리입니다.

2. 병렬 분기에서 A 작업만 완료되면 합류할 수 있나요?

모든 경로를 동기화하는 합류라면 B 경로도 필요한 선행 단계에 도달해야 합니다. 한쪽 완료만으로 진행하지 않습니다.

3. GRAPH 인터록 불만족은 전이를 무조건 막나요?

아닙니다. 인터록은 연결된 동작의 허가에 영향을 줍니다. 진행 차단 요구는 전이·감시 설계를 별도로 검토해야 합니다.

4. Reset과 Start를 분리하는 이유는?

고장 확인·초기화만으로 장치가 바로 재가동하지 않도록 하기 위해서입니다. 예제에서는 새로운 Start 상승 에지가 필요합니다.

5. 예제의 900 상태는 GRAPH 감시와 완전히 같나요?

아닙니다. 이 예제는 별도 고장 상태로 이동합니다. GRAPH 감시는 설정에 따라 현재 단계를 활성 상태로 유지하면서 진행을 차단할 수 있습니다.

확장 과제

  1. 단계별로 정상 전이와 고장 전이를 다른 색으로 표시한 SFC를 그립니다.
  2. 고장 원인을 구분할 FaultCode 출력을 추가합니다. 허가 상실·이송 초과·작업 초과·위치 상실을 구분합니다.
  3. 제품 종류 A/B의 선택 분기를 추가하고 두 조건이 동시에 TRUE일 때 고장 처리합니다.
  4. 독립적인 A/B 준비 병렬 시퀀스를 설계합니다. SCL로 구현한다면 단일 State 변수 하나로 두 경로를 억지로 표현하지 말고 경로별 상태 또는 별도 FB를 검토합니다.

가상 단계 실습 — 활성 단계와 전이를 한 스캔씩

직렬 시퀀스의 현재 상태와 전이 조건을 확인하는 구조 이해용 모형입니다. 센서를 조작한 뒤 “한 스캔 실행”을 누르면 전이를 평가합니다. 실제 PLC·GRAPH 실행 엔진·외부 I/O와 연결하지 않습니다.

이 모형은 앞의 SCL 전체 코드와 달리 시간 경과와 타임아웃을 계산하지 않습니다. 입력 순서 이상·위치 상실·Permit 상실·Reset만 모의합니다. 타이머를 포함한 전체 동작은 별도 TIA Portal 시험표에서 검증해야 합니다.

입력 변경 후 스캔을 실행하면 결과가 갱신됩니다.

0 · 대기활성
10 · 이송비활성
20 · 작업비활성
30 · 완료비활성
900 · 고장비활성
스캔 0 / Step=0 · 대기 MotorCmd=FALSE / WorkCmd=FALSE Done=FALSE / Fault=FALSE 아직 전이 평가 전

    색상만이 아니라 활성/비활성 글자로도 상태를 표시합니다. 입력만 바꾸면 결과는 아직 이전 스캔 값입니다. 한 번의 CASE 평가로 정상 단계 전이는 최대 한 번 수행합니다. 실제 GRAPH의 동작 평가 순서를 재현하는 모형은 아닙니다.

    모형의 우선순위

    1. Reset이면 Permit에 따라 대기 또는 고장으로 이동합니다.
    2. 그 외 Permit이 FALSE이면 고장으로 이동합니다.
    3. 대기에서는 새 Start 에지와 AtPosition·WorkDoneIn 모두 FALSE를 요구합니다.
    4. 이송 중 WorkDoneIn=TRUE면 순서 이상, 아니면 AtPosition=TRUE에서 작업으로 이동합니다.
    5. 작업 중 위치 상실이면 고장, 아니면 WorkDoneIn의 새 상승 에지로 완료합니다.
    6. 완료·고장은 Reset 전까지 유지합니다.

    Start와 WorkDoneIn의 이전 값은 Reset·고장 중에도 매 스캔 갱신합니다. 최초 호출에 Start가 이미 TRUE이면 단순 상승 에지로 인식할 수 있습니다. 전원 복귀 시 반드시 버튼 해제를 확인해야 하는 요구는 별도 재무장 정책이 필요합니다.

    8주차 핵심 정리

    • 단계는 현재 상태, 전이는 이동 조건, 동작은 실행 명령입니다.

    • 인터록은 동작 허가, 감시는 단계의 이상 감지라는 차이가 있습니다.
    • 정상 순서와 함께 고장·시간 초과·초기화·재시작을 설계합니다.
    • SFC 설계와 GRAPH 도구, SCL 대체 구현은 구분합니다.

    공식 문서와 적용 범위

    SFC·GRAPH 개념은 Siemens 공식 자료를 참고했습니다. 가상 장치 요구사항·임의 시간값·SCL 코드·브라우저 모형은 교육용입니다. 브라우저 모형은 시간 초과를 구현하지 않으며 실제 GRAPH 실행을 재현하지 않습니다. 파일 구조·내부 링크·모형의 상태 전이는 생성 과정에서 점검했으나 실제 TIA Portal 컴파일·PLCSIM 실행·브라우저 렌더링 및 클릭 자동 시험은 수행하지 않았습니다. 도구·CPU·버전에 맞는 선언과 동작을 별도로 확인하세요.
