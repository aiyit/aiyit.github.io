S7-1200 / S7-1500 CPU 기능과 차이

제품군의 특징을 이해하고 요구사항에 맞는 CPU를 비교·선정한다

오늘의 학습 목표

  • CPU 제품군의 특징과 개별 모델의 사양을 구분한다.
  • 기존 S7-1200과 S7-1200 G2의 차이를 인지한다.
  • 성능·메모리·I/O·통신·기술 기능을 같은 기준으로 비교한다.
  • 공통 로직과 진단 정보를 활용해 두 CPU를 관찰한다.
  • 선정·교체 시 확인할 근거와 검증 계획을 작성한다.

선수학습: PLC 하드웨어, SCL 기초, 9주차 TIA Portal 하드웨어 구성 / 실습 범위: 오프라인 비교 및 승인된 교육용 환경 / 안전 시운전·생산 설비 교체 제외

1

비교의 출발점 — 제품군과 실제 CPU를 구분하기

S7-1200은 컴팩트한 기계 제어를, S7-1500은 더 높은 성능과 확장성이 필요한 자동화를 검토할 때 자주 비교하는 Siemens SIMATIC PLC 제품군입니다. 그러나 “작은 장비는 무조건 1200, 큰 장비는 무조건 1500”이라는 규칙으로 선택할 수는 없습니다.

같은 제품군 안에서도 CPU 형식, 주문번호, 하드웨어 세대, 펌웨어에 따라 성능·메모리·통신·기술 기능이 달라집니다. 따라서 제품군의 일반적인 특징을 이해한 뒤 실제 모델끼리 비교해야 합니다.

비교 단위: 제품군 → 세대 → 정확한 CPU·주문번호 → 펌웨어 → TIA Portal 지원 조건
S7-1200 G2는 기존 S7-1200과 구분해야 하는 후속 세대입니다. 이 교안은 두 세대를 구분하며 “S7-1200 전체가 항상 같은 성능·모듈 구조”라고 가정하지 않습니다. 모델별 수치는 실습자가 해당 데이터시트에서 확인하도록 구성했습니다.

4

기존 S7-1200과 S7-1200 G2

Siemens는 G2에서 처리 성능·메모리·통신과 모션 기능의 향상, 진단 접근성 개선을 설명합니다. 다만 기능 지원 범위는 CPU, 펌웨어, 엔지니어링 소프트웨어에 따라 확인해야 합니다.

비교 관점검토 사항
하드웨어G2는 기존 S7-1200 모듈과 하드웨어 호환되지 않음
기존 프로그램변환 가능한 경우가 있지만 수정·검증 필요
모션 기능기존 세대의 기능표를 G2에 그대로 적용하지 않음
진단·연결NFC, 웹 서버·API 등의 실제 지원·보호 설정 확인
교체 설계모듈·배선·공간·전원·소프트웨어·시험을 함께 검토
프로그램 이전 가능성과 하드웨어 교체 호환성은 다릅니다. “프로그램이 변환된다”는 말은 기존 모듈과 배선이 그대로 맞는다는 뜻이 아닙니다.

이 수업의 실습 기록에는 CPU 제품명에 G2 여부를 반드시 적습니다. 수치 비교는 기존 세대와 G2를 섞지 않고 데이터시트의 문서 버전도 기록합니다.

F-CPU라는 이유만으로 일반 프로그램에 작성한 정지 논리가 안전 기능이 되는 것은 아닙니다. 안전 요구사항에 적합한 하드웨어·소프트웨어·설계·검증이 모두 필요합니다.

처리 성능을 비교하는 올바른 방법

명령 시간과 실제 사이클 시간은 다릅니다

데이터시트의 비트 연산 시간은 제한된 조건의 지표입니다. 실제 프로그램에는 산술 연산, 블록 호출, 데이터 접근, 통신, 인터럽트와 진단 처리가 섞입니다. 서로 다른 연산 지표를 직접 비교하지 마세요.

항목기록할 내용
데이터시트 지표비트/워드/정수/실수 등 같은 종류의 처리 시간
프로그램 조건동일 로직, 데이터 크기, 호출 주기
실행 환경실제 CPU 모델·펌웨어, 통신 부하, I/O 구성
측정 결과현재·최소·최대 사이클 등 제공 지표
판정 기준요구 응답 시간 충족과 부하 변동의 여유
“CPU A가 몇 배 빠르다”는 결론에는 동일한 비교 기준이 필요합니다. 카탈로그의 가장 빠른 한 수치를 제품군 전체 성능으로 일반화하지 않습니다.
교육용 비교를 위해 생산 PLC에 긴 반복문을 추가하거나 최대 사이클 시간을 늘리지 마세요. 승인된 독립 실습 장치에서만 작은 부하로 측정합니다.

메모리 — 프로그램·데이터·리테인을 나누기

구분역할검토 질문
프로그램 작업 메모리실행 프로그램 저장에 사용하는 자원컴파일된 프로그램과 라이브러리가 들어가는가?
데이터 작업 메모리실행 중 DB·변수 등에 사용하는 자원배열·레시피·통신 버퍼가 충분한가?
로드 메모리프로젝트 적재·보관과 관련된 자원CPU와 메모리 카드의 요구사항은 무엇인가?
리테인 영역정해진 조건에서 값을 유지하는 자원어떤 값을 유지하고 어떤 값은 초기화할 것인가?

메모리 구분과 제공 방식은 CPU별로 확인합니다. 프로그램용과 데이터용 메모리가 분리된 경우 총합만 보고 적합성을 판단하면 한쪽 자원이 부족할 수 있습니다.

리테인은 백업 기능 전체를 대신하지 않습니다. 유지할 값의 범위, 초기화·메모리 리셋·다운로드 동작을 매뉴얼에서 확인하세요. 출력 명령이나 운전 상태를 리테인으로 유지하면 재시작 위험을 따로 검토해야 합니다.

2포트 내장 스위치가 있는 PROFINET 인터페이스 한 개는 독립 네트워크 인터페이스 두 개와 같지 않습니다. 포트 개수와 논리 인터페이스 개수를 구분해야 합니다.

통신 기능 이름이 같아도 클라이언트/서버 역할, 최대 연결 수, 지원 데이터 형식 및 부하 한계가 다를 수 있습니다. 필수 프로토콜은 실제 모델의 지원 표로 검토합니다.

웹 서버나 원격 연결을 지원한다고 외부 인터넷에 직접 공개해도 된다는 뜻은 아닙니다. 필요한 기능만 승인된 접근 제어와 분리된 네트워크 정책에 따라 사용합니다.

S7-1200 계열에도 모션 기능이 있으며 특히 G2의 기능은 기존 세대와 구분해야 합니다. S7-1500도 일반 CPU와 T-CPU의 기술 범위가 같지 않습니다. 요구하는 기술 객체, 축 자원과 드라이브 조합을 먼저 정합니다.

기술 기능은 “있다/없다”로만 비교하지 않습니다. 기능 종류·수량·주기·라이선스·지원 버전까지 맞아야 사용할 수 있습니다.

안전 기능은 일반 시퀀스 로직의 추가 옵션 정도로 취급하지 않습니다. 이번 교안에서는 개념과 선정 체크만 다루며 안전 프로그램 구현 및 승인 절차는 별도 교육 범위입니다.

진단과 유지보수 — 고장 위치를 찾는 경로

S7-1500의 통합 시스템 진단은 TIA Portal, HMI, 웹 서버, 해당 CPU의 디스플레이 등을 통해 상태 정보를 확인하는 체계를 제공합니다. 표시 경로와 사용 조건은 실제 장치에서 확인합니다. 기존 S7-1200과 G2 역시 세대·모델에 맞는 진단 기능을 검토합니다.

진단 경로확인 대상
CPU·모듈 LED전원·RUN/STOP·오류의 기본 상태
Online & Diagnostics장치 정보·진단 버퍼·동작 상태
Device view 진단모듈·채널·장치 구성의 이상
HMI·웹 진단허용된 환경의 상태 표시 및 유지보수
Trace 등 기록 기능지원되는 CPU의 시간 변화·이벤트 분석
STOP 상태에서도 진단 정보를 볼 수 있는 기능과 출력이 안전한 상태라는 판단은 별개입니다. 진단 화면을 확인하기 위해 무단 STOP/RUN 전환·리셋·구성 변경을 수행하지 않습니다.

진단 실습은 기존 상태를 읽는 방식으로 시작합니다. 실제 장치에서 모듈을 뽑거나 통신 케이블을 끊는 고장 유발 시험은 별도 승인과 안전 절차 없이는 하지 않습니다.

비교 실습 2 — 동일 로직과 진단 확인

지원되는 교육용 환경에서만 진행합니다. 전역 DB LabCPU에 Enable : Bool, Values : Array[0..4] of Int, Total : DInt, Average : Real, Valid : Bool을 선언합니다. SCL FC의 Temp에 i : Int를 선언하고 매 스캔 호출합니다.

// 실제 출력과 연결하지 않는 공통 로직
"LabCPU".Total := 0;
"LabCPU".Average := 0.0;
"LabCPU".Valid := FALSE;

IF "LabCPU".Enable THEN
    FOR #i := 0 TO 4 DO
        "LabCPU".Total := "LabCPU".Total
            + INT_TO_DINT("LabCPU".Values[#i]);
    END_FOR;
    "LabCPU".Average := DINT_TO_REAL("LabCPU".Total) / 5.0;
    "LabCPU".Valid := TRUE;
END_IF;
입력예상 결과
Enable=FALSETotal=0, Average=0.0, Valid=FALSE
Enable=TRUE, Values=[10,20,30,40,50]Total=150, Average=30.0, Valid=TRUE
Enable=TRUE, Values=[-5,-10,0,10,5]Total=0, Average=0.0, Valid=TRUE
  1. 별도 프로젝트 또는 승인된 장치 구성으로 두 CPU용 코드를 컴파일합니다.
  2. 동일 입력에서 결과가 같은지 확인합니다.
  3. 제공되는 진단 화면에서 CPU 정보·진단 버퍼·사이클 정보를 읽습니다.
  4. CPU·펌웨어·통신 조건과 함께 관찰값을 기록합니다.
이 짧은 예제로 두 CPU의 성능 배수를 산출하지 않습니다. 실습 목적은 로직 이식 시 인터페이스·컴파일·결과·진단 경로를 확인하는 것입니다. 시뮬레이터 실행 시간을 실제 CPU 성능으로 간주하지 마세요.

확인 문제와 제출 과제

1. S7-1500에는 내장 I/O가 전혀 없나요?

아닙니다. 내장 I/O가 있는 Compact(C) CPU도 있습니다. 정확한 모델의 채널 구성을 확인합니다.

2. 기존 S7-1200 모듈을 G2에 그대로 사용해도 되나요?

아닙니다. G2는 기존 S7-1200 하드웨어와 호환되지 않습니다. 기존 프로그램의 변환 가능성과 모듈 호환성을 구분해야 합니다.

3. 2포트이면 독립 인터페이스가 두 개인가요?

반드시 그렇지 않습니다. 하나의 PROFINET 인터페이스에 2포트 스위치가 포함된 구성일 수 있습니다.

4. 비트 연산 시간이 절반이면 설비 응답도 절반인가요?

아닙니다. 프로그램 구성, I/O 갱신, 통신, 구동 장치 응답 등이 함께 영향을 줍니다.

5. F-CPU에 일반 SCL 정지 코드를 넣으면 안전 기능인가요?

아닙니다. 적합한 안전 설계·프로그램·I/O·도구와 검증이 필요합니다.

6. 두 제품군 중 어떤 것이 더 좋은가요?

요구 기능·응답·메모리·통신·공간·유지보수 조건을 충족하는 실제 CPU가 적합합니다. 제품군 이름만으로 우열을 확정할 수 없습니다.

  1. CPU 두 대의 주문번호·세대·펌웨어가 있는 비교표
  2. 데이터시트의 항목별 근거와 문서 버전
  3. 공통 로직 시험 결과 또는 실행하지 못한 항목의 이유
  4. 가상 장비에 적합한 후보와 선정 근거 세 가지
  5. 향후 확장·전환 시 위험 요소 두 가지

10주차 핵심 정리

  • S7-1200은 컴팩트 구성, S7-1500은 폭넓은 성능·확장 요구를 중심으로 검토합니다.
  • 실제 적합성은 정확한 모델·세대·주문번호·펌웨어로 판단합니다.
  • G2는 기존 S7-1200과 하드웨어 호환되지 않습니다.
  • C·F·T 등 형식의 기능과 소프트웨어 조건을 확인합니다.
  • 명령 처리 시간과 전체 설비 응답 시간은 다릅니다.
  • 필수 조건 → 데이터시트 비교 → 검증 → 비용·유지보수 순서로 선정합니다.
