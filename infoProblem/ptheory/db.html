DATABASE & SQL

데이터베이스·SQL 이론

데이터 모델링부터 SQL 작성, 트랜잭션과 데이터베이스 관리까지 핵심 개념을 학습한다.

1. 데이터베이스의 기본 개념

데이터베이스(Database)는 여러 사용자가 공유하고 효율적으로 관리할 수 있도록 데이터를 통합해 저장한 집합이다. DBMS(Database Management System)는 데이터베이스를 생성·조회·수정·삭제하고 접근을 제어하는 소프트웨어다.

개념설명
데이터관찰하거나 측정한 사실과 값
정보데이터를 처리해 의미 있는 형태로 만든 결과
DBMS데이터 정의, 조작, 제어, 보안 및 백업 기능 제공
스키마데이터베이스의 구조와 제약조건에 대한 정의
인스턴스특정 시점에 데이터베이스에 실제 저장된 데이터 상태

DBMS의 주요 기능

정의(DDL), 조작(DML), 제어(DCL), 트랜잭션 관리, 무결성 유지, 동시성 제어, 보안 및 회복 기능을 제공한다.

2. 관계형 데이터 모델

관계형 데이터베이스는 데이터를 테이블(릴레이션) 형태로 표현한다. 행은 튜플(tuple), 열은 속성(attribute)이며 각 속성은 도메인이라는 허용 값의 범위를 가진다.

용어의미
릴레이션행과 열로 구성된 테이블
튜플테이블의 한 행, 레코드
속성테이블의 열, 필드
도메인속성이 가질 수 있는 값의 집합
차수(Degree)속성의 수
카디널리티(Cardinality)튜플의 수

키(Key)의 종류

  • 슈퍼키: 튜플을 유일하게 식별할 수 있는 속성 집합
  • 후보키: 유일성과 최소성을 만족하는 슈퍼키
  • 기본키(PK): 후보키 중 대표로 선택한 키. 중복과 NULL을 허용하지 않는다.
  • 대체키: 기본키로 선택되지 않은 후보키
  • 외래키(FK): 다른 테이블의 기본키 등을 참조하는 속성
  • 복합키: 두 개 이상의 속성을 조합한 키

3. 데이터 무결성과 정규화

무결성은 데이터가 정확하고 일관된 상태를 유지하는 성질이다.

무결성 종류핵심 내용
개체 무결성기본키는 중복되거나 NULL일 수 없다.
참조 무결성외래키 값은 참조 대상에 존재하거나 NULL이어야 한다(제약조건 설정에 따름).
도메인 무결성속성 값은 정의된 자료형과 허용 범위를 지킨다.
사용자 정의 무결성업무 규칙에 따른 별도 제약조건을 적용한다.

정규화(Normalization)

데이터 중복을 줄이고 삽입·삭제·갱신 이상 현상을 방지하기 위해 테이블을 구조화하는 과정이다.

단계조건 요약
제1정규형(1NF)모든 속성 값이 원자값(더 이상 나눌 수 없는 값)
제2정규형(2NF)1NF이며 부분 함수 종속 제거
제3정규형(3NF)2NF이며 이행 함수 종속 제거
BCNF모든 결정자가 후보키인 상태

정규화 수준이 높아지면 중복은 줄지만 조회 성능이나 조인 비용을 고려해 반정규화를 적용하기도 한다.

4. SQL 명령어 분류

SQL(Structured Query Language)은 관계형 데이터베이스의 데이터를 정의하고 조작하며 제어하는 표준 언어다.

분류기능대표 명령
DDL데이터 구조 정의CREATE, ALTER, DROP, TRUNCATE
DML데이터 조회·삽입·수정·삭제SELECT, INSERT, UPDATE, DELETE
DCL권한 제어GRANT, REVOKE
TCL트랜잭션 제어COMMIT, ROLLBACK, SAVEPOINT

테이블 생성과 데이터 입력

CREATE TABLE student (
  id INT PRIMARY KEY,
  name VARCHAR(30) NOT NULL,
  dept VARCHAR(30),
  score INT CHECK (score BETWEEN 0 AND 100)
);

INSERT INTO student (id, name, dept, score)
VALUES (1, '김민수', 'AI소프트웨어', 90);

5. SELECT와 조건 검색

SELECT는 테이블에서 원하는 데이터를 조회하는 명령이다. 기본 구조는 다음과 같다.

SELECT 컬럼명
FROM 테이블명
WHERE 조건
GROUP BY 그룹 기준
HAVING 그룹 조건
ORDER BY 정렬 기준;

자주 사용하는 연산자와 함수

종류문법 예설명
비교=, <>, >, <=값 비교
논리AND, OR, NOT조건 결합
범위BETWEEN 70 AND 90범위 검색(양 끝 포함)
목록IN ('A','B')목록에 포함되는 값
패턴LIKE '김%'문자 패턴 검색
NULLIS NULLNULL 여부 확인
집계COUNT, SUM, AVG, MAX, MIN그룹 또는 전체 집계
-- 점수가 80 이상인 학생을 점수 내림차순으로 조회
SELECT name, score
FROM student
WHERE score >= 80
ORDER BY score DESC;

-- 학과별 학생 수와 평균 점수
SELECT dept, COUNT(*) AS student_count, AVG(score) AS avg_score
FROM student
GROUP BY dept
HAVING AVG(score) >= 70;

논리적 처리 순서는 일반적으로 FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY 순서로 이해한다.

6. 조인(JOIN)과 서브쿼리

조인은 두 개 이상의 테이블을 관련 열을 기준으로 연결해 조회하는 방법이다.

종류설명
INNER JOIN양쪽 테이블에서 조인 조건이 일치하는 행만 반환
LEFT OUTER JOIN왼쪽 테이블의 모든 행과 일치하는 오른쪽 행 반환
RIGHT OUTER JOIN오른쪽 테이블의 모든 행과 일치하는 왼쪽 행 반환
FULL OUTER JOIN양쪽의 모든 행을 반환하며 미일치 부분은 NULL 처리
CROSS JOIN두 테이블 행의 모든 조합(카티션 곱)
SELF JOIN하나의 테이블을 자기 자신과 조인
SELECT s.name, d.dept_name
FROM student s
INNER JOIN department d
  ON s.dept_id = d.dept_id;

서브쿼리는 SQL 문 안에 포함된 SELECT 문이다. 단일 행·다중 행·상관 서브쿼리 등으로 구분한다.

-- 전체 평균보다 점수가 높은 학생
SELECT name, score
FROM student
WHERE score > (SELECT AVG(score) FROM student);

7. 뷰, 인덱스, 트랜잭션

뷰(View)

하나 이상의 테이블을 기반으로 만든 가상 테이블이다. 복잡한 질의를 단순화하고 데이터 접근 범위를 제한하는 데 활용한다.

CREATE VIEW high_score AS
SELECT id, name, score
FROM student
WHERE score >= 90;

인덱스(Index)

검색 속도를 높이기 위한 자료구조다. 조회 성능을 개선할 수 있지만 저장 공간이 필요하고 INSERT·UPDATE·DELETE 때 유지 비용이 발생한다.

CREATE INDEX idx_student_name
ON student(name);

트랜잭션(Transaction)과 ACID

속성설명
원자성(Atomicity)모든 작업이 수행되거나 전혀 수행되지 않는다.
일관성(Consistency)트랜잭션 전후 데이터 무결성 규칙을 만족한다.
격리성(Isolation)동시에 실행되는 트랜잭션이 서로 간섭하지 않도록 한다.
지속성(Durability)COMMIT된 결과는 장애 후에도 보존된다.
BEGIN;
UPDATE account SET balance = balance - 10000 WHERE id = 1;
UPDATE account SET balance = balance + 10000 WHERE id = 2;
COMMIT; -- 확정
-- 오류가 발생했다면 ROLLBACK으로 취소
