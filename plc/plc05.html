5주차 · Module 05

래더 다이어그램(LD) 심화

자기유지·우선순위·에지·인터록을 스캔 단위로 이해한다

오늘의 학습 목표

  • 접점·코일과 물리 배선의 의미를 구분한다.
  • 정지 우선 자기유지와 Set/Reset 우선순위를 설명한다.
  • 레벨 시작과 상승 에지 시작의 차이를 시험한다.
  • 상태 기억·실행 순서·중복 코일 문제를 찾는다.
  • 실제 출력 없이 내부 태그로 정상·정지·재시작 조건을 검토한다.

선수학습: 1~4주차 / 준비물: 웹 브라우저·기록 도구 / 선택 실습: 지원되는 TIA Portal·시뮬레이터 / 실제 I/O·모터·안전 제어 제외

1

LD를 읽는 기준 — 배선도가 아니라 실행 논리

LD(Ladder Diagram)는 접점·코일·블록과 연결선으로 논리를 표현하는 그래픽 언어입니다. Siemens TIA Portal에서는 LAD라는 명칭으로 만납니다. 이번 주에는 단순 AND/OR를 넘어 호출 사이 상태 기억, 우선순위, 에지와 상호 배제를 학습합니다.

접점은 태그의 상태를 검사하고 일반 코일은 논리 결과를 변수에 대입합니다. 도식의 선은 물리적으로 흐르는 전력을 재현하는 것이 아닙니다.

세 가지를 따로 읽습니다: 현재 입력 → 이번 네트워크 계산 → 다음 계산에 남는 변수값
문자 도식은 읽기용 개념도이며 TIA Portal로 가져올 수 있는 LAD 프로젝트 파일이 아닙니다. 실제 출력·모터·안전 회로에 연결하지 않고 내부 태그로만 학습합니다.
2

[ A ]정상 논리 접점A=TRUE이면 논리 경로가 참
[/ B ]부정 논리 접점B=FALSE이면 논리 경로가 참

Lamp = Enable AND NOT Blocked

Blocked=TRUE이면 부정 논리 접점은 거짓입니다. 물리 NC 버튼을 연결했는지와는 별개입니다. 먼저 입력 태그의 TRUE 의미를 정의하고 그 값을 어떻게 검사할지 선택합니다.

코일의 네트워크가 실행되지 않으면 값을 갱신하지 않을 수 있습니다. “논리 경로 FALSE로 코일을 실행하는 것”과 “그 네트워크 자체를 건너뛰는 것”은 다릅니다.

RunMemory는 현재 네트워크에서 쓰기 전 값으로 읽히고, 코일을 계산한 뒤 새 값으로 갱신됩니다. 이전 값을 읽는 자기유지 구조와 여러 곳에서 같은 태그에 쓰는 구조를 구분하세요.

이 방식은 Start가 레벨 신호이면 Permit 복구나 StopReq 해제 시 Start가 계속 TRUE일 때 다시 운전할 수 있습니다. 재시작 방지가 필요하면 새 상승 에지를 요구하는 정책으로 확장합니다.

4

Set/Reset — 동시 입력의 우선순위

Set은 상태를 TRUE로 저장하고 Reset은 FALSE로 저장하는 기능입니다. 둘 다 요청되지 않을 때 이전 상태를 유지합니다. 그러나 동시에 요청되었을 때는 Set 우선과 Reset 우선을 구분해야 합니다.

SetResetReset 우선 결과Set 우선 결과
FALSEFALSE이전 상태이전 상태
TRUEFALSETRUETRUE
FALSETRUEFALSEFALSE
TRUETRUEFALSETRUE

일반 정지 우선 운전 기억에는 충돌 시 FALSE가 되는 정책이 적합한 출발점입니다. 하지만 안전 기능은 이것만으로 구현되지 않으며 모든 공정이 같은 정책을 쓰는 것은 아닙니다.

RS/SR 이름만 보고 우선순위를 외우지 않습니다. 제조사·명령군·기종의 명령 도움말에서 S/R 입력 이름, 진리표와 우선순위를 확인하세요. 서로 다른 PLC 매뉴얼의 표기를 섞지 않습니다.

여러 네트워크에 Set 코일과 Reset 코일을 흩어 놓으면 실행 순서에 의해 결과를 해석해야 하는 경우가 생깁니다. 상태를 바꾸는 위치와 우선순위를 한눈에 확인할 수 있게 설계합니다.

레벨은 현재 신호가 TRUE인지이고, 상승 에지는 이전 호출의 FALSE가 이번 호출에서 TRUE로 바뀌었는지입니다. 시작 입력을 계속 누르고 있어도 새 상승 에지는 한 번만 발생합니다.

PrevStart는 Reset·StopReq 중에도 매 스캔 갱신합니다. 그렇지 않으면 이미 눌린 버튼을 정지 해제 후 새 에지로 잘못 인식할 수 있습니다.
시작 시 PrevStart=FALSE이고 첫 스캔에 Start=TRUE이면 이 단순 에지 검출은 상승 에지로 판단합니다. 전원 재투입 때 버튼 해제 확인까지 필요하면 별도 시동 허가·재무장 정책을 설계해야 합니다.
6

정지·Reset 우선, 새 에지로 시작하는 설계

이번 가상 실습의 요구사항입니다. RunMemory·PrevStart는 호출 간 유지되는 내부 변수이며 처음 값은 FALSE입니다.

  1. Permit이 없거나 StopReq·Reset 중 하나라도 TRUE이면 RunMemory를 FALSE로 만듭니다.
  2. 그 외에는 새로운 StartEdge가 있으면 RunMemory를 TRUE로 만듭니다.
  3. StartEdge가 없으면 기존 상태를 유지합니다.
  4. 출력 표시 RunCmd는 RunMemory와 현재 허가·정지 조건으로 최종 결정합니다.
Network 1: StartEdge = Start AND NOT PrevStart
Network 2: PrevStart = Start

Network 3: 정지·Reset 우선 운전 기억
|--[Permit]--[/StopReq]--[/Reset]--+--[StartEdge]--+--(RunMemory)--|
|                                 |               |
|                                 +--[RunMemory]--+

Network 4: 최종 가상 명령
|--[RunMemory]--[Permit]--[/StopReq]--[/Reset]--(RunCmd)--|

네트워크 순서가 중요합니다. 에지 계산 → 이전 입력 저장 → 운전 기억 → 최종 명령 순서로 한 호출에서 실행합니다.

Reset은 새 시작 명령이 아닙니다. Permit 복구·StopReq 해제·Reset 해제만으로 시작하지 않도록 시험합니다. 단, 앞서 설명한 첫 호출 에지 정책과 입력 펄스 누락 가능성은 별도 검토합니다.

9

가상 한 스캔 실습 — 레벨과 에지 비교

입력 버튼은 다음 가상 스캔에 쓸 값을 변경합니다. “한 스캔 실행”을 눌러야 기억 상태가 갱신됩니다. 실제 PLC·자동 주기·시간·I/O에 연결하지 않는 논리 학습 도구입니다.

입력·초기 상태 확인 후 한 스캔을 실행하세요.

스캔 0 PrevStart=FALSE / StartEdge=FALSE RunMemory=FALSE / RunCmd=FALSE

    출력은 마지막으로 실행한 가상 스캔의 결과입니다. 입력만 바꾸고 스캔하지 않으면 결과는 바뀌지 않습니다. 방식 변경 시 기억·에지·스캔 기록은 초기화되며 현재 입력값은 유지합니다. 전체 초기화는 입력도 모두 FALSE로 만듭니다.

    실제 PLC는 지정된 실행 규칙으로 자동 반복합니다. 이 모형은 계산 순서를 천천히 보기 위한 수동 단일 스텝이며 실제 PLC의 안전 반응이나 응답 시간을 재현하지 않습니다.

    확인 문제와 제출 과제

    1. 자기유지에 RunMemory 접점을 병렬로 넣는 이유는?

    시작 입력이 사라져도 이전 운전 기억이 참인 동안 유지 조건을 만들기 위해서입니다.

    2. Start와 StopReq가 동시에 TRUE이면?

    이 교안의 정지 우선 로직에서는 RunMemory가 FALSE가 됩니다.

    3. 에지 계산보다 PrevStart 저장을 먼저 하면?

    현재 Start와 PrevStart가 같아져 상승 에지를 검출하지 못할 수 있습니다.

    4. StopReq 동안에도 PrevStart를 갱신해야 하나요?

    이 설계에서는 그렇습니다. 정지 중 발생한 버튼 상태를 기록해 해제 시 잘못된 새 에지로 해석하지 않게 합니다.

    5. 최초 호출에서 Start=TRUE이면 에지 시작이 불가능한가요?

    이 단순 모델은 PrevStart 초기값이 FALSE여서 첫 호출을 에지로 판단합니다. 반드시 해제 후 재누름을 요구하려면 별도 시동 재무장 정책이 필요합니다.

    6. 소프트웨어 상호 배제만으로 실제 정역 제어가 완성되나요?

    아닙니다. 전기·기계 인터록, 피드백·정지 확인·보호·안전 설계 등이 추가로 필요합니다.

    제출 항목

    1. 정지 우선 자기유지 도식과 설명
    2. 레벨·에지 방식의 차이를 보이는 시험 기록
    3. Set/Reset 동시 입력의 우선순위 진리표
    4. 중복 코일·초기화·첫 호출 위험에 대한 개선 의견
    5. 선택 실습을 했다면 인터페이스·컴파일·시뮬레이션 결과 및 미실행 항목

    다음 주: 기능 블록 다이어그램(FBD) 실습

    같은 논리와 상태를 블록 연결로 표현하고 블록 입력·출력·상태·인스턴스를 함께 읽는 방법을 학습합니다.

    5주차 핵심 정리

    • LD는 태그를 검사하고 결과를 대입하는 실행 논리입니다.
    • 자기유지는 이전 상태를 사용하며 정지·Reset의 우선순위를 명시합니다.
    • 새 시작 이벤트와 버튼이 계속 눌린 상태는 다릅니다.
    • 에지 계산 후 PrevStart를 저장하고, 정지 중에도 갱신합니다.
    • 첫 호출·전원 복귀의 재무장 정책은 별도 설계가 필요합니다.
    • 상호 배제와 실제 안전·보호 회로는 다른 층위입니다.
