12주차 · Module 12

모터 기동·정역·인버터 제어

명령과 피드백을 구분하고 인터록·정지 확인·속도 지령을 설계한다

오늘의 학습 목표

  • 직입 기동과 인버터 운전의 차이를 설명한다.
  • 정역 접촉기 인터록과 정지 확인의 역할을 구분한다.
  • 내부 DB 기반 정역 시퀀스와 고장 처리를 구현한다.
  • 인버터 명령·상태·속도 지령의 관계와 단위를 이해한다.
  • 정상·방향 충돌·정지 실패 시나리오를 가상 입력으로 시험한다.

선수학습: I/O·SCL·타이머·11주차 단계 제어 / 대상: TIA Portal 지원 교육 환경 / 실습: 내부 태그만 사용 / 전력 결선·실물 시운전·안전 제어 제외

1

실습 범위와 안전 경계

이번 주에는 모터의 기동·정지·회전 방향·속도 지령을 PLC에서 어떻게 구분하여 다루는지 배웁니다. 접촉기 기반 정역 운전과 인버터 운전은 장치 구성과 제어 방식이 다르므로 별도 사례로 학습합니다.

실습은 내부 DB 태그만 사용합니다. 실제 모터·접촉기·인버터 출력에 연결하지 않습니다. 전력회로 결선·활선 측정·실물 시운전은 포함하지 않습니다.
  • PLC 출력은 모터 전력을 직접 공급하는 단자가 아닙니다. 실제 구동 회로에는 적합한 개폐·보호·인터페이스 구성이 필요합니다.
  • 소프트웨어 인터록은 하드웨어 인터록이나 안전 기능을 대신하지 않습니다.
  • Stop 버튼, PLC 출력 OFF, 인버터 운전 명령 OFF를 전기적 격리로 간주하지 않습니다.
  • 실물 작업은 자격을 갖춘 담당자가 제조사 절차와 현장 에너지 차단·확인 절차에 따라 수행해야 합니다.

명판·보호장치·정지 방식·역회전 허용 여부를 확인하지 않은 상태에서 예제 코드를 설비에 적용하지 마세요.

2

기동 방식의 차이 — 직입·소프트스타터·인버터

방식개념PLC가 주로 주고받는 정보
직입 기동접촉기로 전원을 연결하여 기동운전 요청, 접촉기 피드백, 과부하 상태
소프트스타터기동·정지 과정의 전압 등을 제어기동 허가, 운전 상태, 고장 상태
인버터, VFD주파수·전압 등을 제어해 속도 운전운전·정지, 속도 지령, 준비·실속도·고장

단순 ON/OFF 요구와 속도 제어 요구를 먼저 구분합니다. 기동 전류, 부하 특성, 가감속, 정지 요구, 허용 기동 횟수는 장치 선정 시 별도로 검토합니다. 특정 방식이 모든 부하에 적합한 것은 아닙니다.

이 교안의 정역 접촉기 논리와 인버터 논리를 같은 실제 출력에 함께 연결하지 않습니다. 두 실습은 서로 다른 가상 장치 사례입니다.
3

기동·정지의 기본 — 요청과 상태를 구분하기

종류예시의미
명령RunCmd운전하라는 요청
피드백ContactorOn 또는 DriveRunning장치에서 확인된 상태
허가Permit, OverloadOK일반 운전 조건의 충족 여부
고장Fault, FaultCode이상과 원인 기록

명령을 ON 했다는 사실은 접촉기가 붙었거나 축이 실제로 회전한다는 증거가 아닙니다. 피드백을 이용해 기동 실패, 정지 실패, 방향 충돌을 감시해야 합니다.

// 자기유지 논리의 개념: RunMemory는 FB Static Bool
IF NOT #Permit OR #StopReq THEN
    #RunMemory := FALSE;
ELSIF #StartEdge THEN
    #RunMemory := TRUE;
END_IF;
#RunCmd := #RunMemory AND #Permit AND NOT #StopReq;
이 짧은 예제에는 피드백·타임아웃·접촉기 고착 감시가 없습니다. 실제 제어용 완성 코드가 아니라 정지 우선 자기유지 개념입니다. StartEdge는 매 스캔 평가한 상승 에지여야 합니다.
4

정역 접촉기 — 세 겹의 상호 배제

3상 유도전동기의 일반적인 접촉기 정역 회로는 두 상의 순서를 바꾸는 구조를 사용합니다. 정회전·역회전 접촉기가 동시에 투입되면 위험한 상간 단락이 생길 수 있으므로 실제 장치는 검증된 정역 조합과 보호 구성이 필요합니다.

인터록역할한계
소프트웨어두 방향 명령의 동시 출력 방지CPU·배선·접점 고장을 단독으로 막지 못함
전기적반대편 접촉기 보조 접점을 이용한 코일 상호 차단적합한 접점·배선·설계 필요
기계적두 접촉기의 동시 동작을 기계적으로 억제맞는 조합과 제조사 장착 규칙 필요

Siemens SIRIUS 정역 접촉기 조합에는 전기적·기계적 인터록을 함께 갖춘 제품이 있습니다. 모든 임의 조합에 같은 기능이 있다고 가정하지 마세요.

코드에서 FwdCmd AND RevCmd가 항상 FALSE여야 합니다. 그러나 이 불변조건을 만족해도 실제 주접점 고착이나 배선 오류까지 검증된 것은 아닙니다.
5

방향 전환 정책 — 정지 후 새 명령

이번 가상 실습은 운전 중 반대 방향 버튼을 누르면 운전을 취소하고 정지 확인 단계로 이동합니다. 반대 방향 요청은 예약하지 않으며, 정지 확인이 끝난 뒤 새로운 버튼 상승 에지가 필요합니다.

정회전 / 역회전→명령 OFF→접촉기 해제 + 정지 확인→확인 시간 유지→대기→새 방향 시작
  • 두 방향 버튼 동시 입력은 고장으로 처리합니다.
  • 정지 확인에는 두 접촉기 피드백 OFF와 가상 ZeroSpeed=TRUE를 사용합니다.
  • 확인 조건이 0.5초 연속 유지되면 대기로 갑니다.
  • 정지 확인이 5초 안에 끝나지 않으면 고장으로 처리합니다.
0.5초는 정지 확인 신호의 교육용 안정 시간이지 모터가 멈춘다는 보증 시간이 아닙니다. ZeroSpeed도 일반 가상 Bool이므로 안전 인증 정지 검출이 아닙니다. 실제 정지 검출·지연·제동은 부하와 제조사 사양에 맞춰 설계합니다.
6

실습 A — 정역 제어 인터페이스

InputPermit, OverloadOK각각 Bool, 일반 운전 조건

SCL FB FB_MotorReverse를 만들고 위 인터페이스를 선언합니다. 편집기에서 TON을 삽입해 StopStable, StopLimit 멀티인스턴스를 생성합니다. LabMotor 전역 DB에 Input·Output과 같은 이름·자료형의 변수를 만들고 별도 인스턴스 DB로 매 스캔 호출합니다.

초기값 State=0은 시작 후에도 정지 검증을 거치게 하기 위한 값입니다. Permit·OverloadOK·ZeroSpeed를 TRUE, 접촉기 피드백은 FALSE로 준비한 뒤 Reset을 입력합니다. 실제 입출력 주소는 할당하지 않습니다.
7

실습 A — 정역 SCL 예제

// 시작 에지는 모든 스캔에서 평가
#FwdEdge := #StartFwd AND NOT #PrevFwd;
#RevEdge := #StartRev AND NOT #PrevRev;
#PrevFwd := #StartFwd;
#PrevRev := #StartRev;

#StopConfirmed := NOT #FwdFb AND NOT #RevFb AND #ZeroSpeed;
#StopStable.TON(IN := (#State = 0) AND #StopConfirmed AND NOT #Reset,
                PT := T#500ms);
#StopLimit.TON(IN := (#State = 0) AND NOT #Reset, PT := T#5s);

// 고장 래치: 최초 코드 유지
IF NOT #Permit OR NOT #OverloadOK THEN
    IF #State <> 900 THEN
        #ErrorCode := 1;
    END_IF;
    #State := 900;
ELSIF (#StartFwd AND #StartRev) OR (#FwdFb AND #RevFb) THEN
    IF #State <> 900 THEN
        #ErrorCode := 2;
    END_IF;
    #State := 900;
ELSIF #Reset THEN
    #State := 0; // Reset 후에도 정지 검증부터
    #ErrorCode := 0;
ELSIF #State = 900 THEN
    #State := 900;
ELSE
    CASE #State OF
        0: // 출력 OFF, 정지 확인
            IF #StopLimit.Q THEN
                #ErrorCode := 3;
                #State := 900;
            ELSIF #StopStable.Q THEN
                #State := 10;
            END_IF;
        10: // 기동 가능한 대기
            IF NOT #StopConfirmed THEN
                #State := 0;
            ELSIF NOT #StopReq THEN
                IF #FwdEdge THEN
                    #State := 20;
                ELSIF #RevEdge THEN
                    #State := 30;
                END_IF;
            END_IF;
        20: // 정회전
            IF #RevFb THEN
                #ErrorCode := 4;
                #State := 900;
            ELSIF #StopReq OR #StartRev THEN
                #State := 0;
            END_IF;
        30: // 역회전
            IF #FwdFb THEN
                #ErrorCode := 4;
                #State := 900;
            ELSIF #StopReq OR #StartFwd THEN
                #State := 0;
            END_IF;
        ELSE
            #ErrorCode := 99;
            #State := 900;
    END_CASE;
END_IF;

// 최종 명령: 동시 출력 방지 + 반대 피드백 인터록
#FwdCmd := (#State = 20) AND #Permit AND #OverloadOK
           AND NOT #StopReq AND NOT #Reset AND NOT #RevFb;
#RevCmd := (#State = 30) AND #Permit AND #OverloadOK
           AND NOT #StopReq AND NOT #Reset AND NOT #FwdFb;
#Fault := (#State = 900);
#StepNo := #State;
#FaultCode := #ErrorCode;

단계와 코드

값의미
State 0 / 10 / 20 / 30 / 900정지 검증 / 대기 / 정회전 / 역회전 / 고장
FaultCode 1실행 허가 또는 과부하 정상 조건 상실
FaultCode 2양방향 버튼 또는 양방향 피드백 동시 입력
FaultCode 3정지 검증 시간 초과
FaultCode 4운전 방향과 반대 접촉기 피드백
FaultCode 99정의되지 않은 상태
이 예제는 기동 후 해당 접촉기 ON 피드백이 일정 시간 안에 들어오는지 감시하지 않습니다. 따라서 실제 접촉기 기동 실패를 완전하게 검출하지 못합니다. 피드백 모델·고착·속도 센서 고장은 별도 설계해야 하며, 실물 적용 코드가 아닙니다.

인버터 제어 — 운전 명령과 속도 지령

인버터는 접촉기 정역 회로와 달리 드라이브 내부 제어로 주파수와 방향 등을 다룹니다. 전동기 특성·정격 입력과 운전 모드를 제조사 지침에 맞게 설정해야 합니다.

연결 방식명령·지령확인 사항
디지털 I/O운전/정지, 방향, 고정 속도 선택단자 기능·활성 레벨·2선/3선 제어
아날로그 + 디지털속도 지령과 운전 명령0~10V/4~20mA 범위·단선 처리·스케일
PROFINET 등 통신제어워드·속도 지령 / 상태워드·실속도텔레그램·드라이브 상태 전이·통신 감시
PLC: 운전·속도 요청→인버터: 상태·가감속 제어→모터

Siemens의 SINAMICS G120X 속도 제어 예제는 SINA_SPEED와 표준 텔레그램 1을 사용하여 제어워드·속도 지령을 보내고 상태워드·실속도를 받습니다. 다른 모델·텔레그램·라이브러리에서 같은 비트 배열을 가정하면 안 됩니다.

운전 중인 인버터 출력 측의 상을 접촉기로 바꾸어 정역 운전하는 방식을 이 교안의 실습으로 사용하지 않습니다. 실제 출력 측 개폐와 허용 조건은 드라이브·모터 제조사 지침과 전문 설계를 따릅니다.
10

속도 스케일링 — 단위와 기준값부터

이번 연습은 가상 속도 지령 0~50Hz를 0~100%로 환산합니다. 50Hz는 단순 교육용 기준이며 실제 모터·인버터의 상한이 아닙니다. 구동 주파수와 기계 회전수의 관계도 모터 극수·슬립·제어 방식에 따라 달라집니다.

// Input: RequestedHz : Real
// Output: LimitedHz, SpeedPercent : Real
// 전제: 유한한 정상 Real 입력, 허용 범위 0~50Hz인 가상 장치
#LimitedHz := #RequestedHz;
IF #LimitedHz < 0.0 THEN
    #LimitedHz := 0.0;
ELSIF #LimitedHz > 50.0 THEN
    #LimitedHz := 50.0;
END_IF;
#SpeedPercent := (#LimitedHz / 50.0) * 100.0;
입력 Hz제한 후 Hz백분율
-5.00.00.0%
25.025.050.0%
50.050.0100.0%
60.050.0100.0%

만약 가상 아날로그 출력에서 “0~27648이 0~50Hz”라고 별도로 정의했다면 다음처럼 계산할 수 있습니다. 이 수치를 모든 아날로그 모듈이나 통신 텔레그램에 적용하지 마세요.

// AnalogRaw : Int (Output), 위 가상 스케일에서만 사용
#AnalogRaw := REAL_TO_INT((#LimitedHz / 50.0) * 27648.0);
실제 통신 속도 지령은 Hz가 아니라 기준 속도에 정규화된 정수일 수 있습니다. 단위·부호·기준값·정격 속도·범위를 먼저 확인합니다. 위 코드에는 비정상 부동소수점 값(NaN 등) 검사가 없습니다.

실습 B — 인버터 상태 전이 설계

가상 단계명령·처리다음 조건
0 · 준비 대기RunRequest=FALSE, 지령 0DriveReady AND 새 Start → 10
10 · 운전RunRequest=TRUE, 제한된 속도 지령Stop 또는 반대 방향 요구 → 20
20 · 감속 요청일반 정지 요청, 새 방향 운전 금지정지 상태 확인 → 0
900 · 고장운전 요청 해제, 고장 기록원인 제거 후 승인된 확인·Reset

이 표는 상위 시퀀스의 설계도이며 드라이브 상태기계를 대체하지 않습니다. RunRequest·StopRequest를 실제 제어워드로 바꾸는 처리는 해당 드라이브 매뉴얼이나 검증된 라이브러리가 담당해야 합니다.

  • 준비 완료와 운전 중 상태를 별도로 읽습니다.
  • 통신 이상과 드라이브 고장을 다른 원인으로 기록합니다.
  • 반대 방향 요구는 감속·정지 확인 후 새로운 시작으로 처리합니다.
  • 실속도·상태워드가 정상이어도 안전 인증 정지 확인과는 구분합니다.
  • 드라이브 고장 확인과 PLC 시퀀스 Reset은 필요에 따라 분리합니다.
수동으로 임의의 제어워드 상수를 쓰거나 상태워드의 한 비트만 보고 운전 가능 여부를 판단하지 않습니다. 먼저 선택한 텔레그램의 정의와 라이브러리 인터페이스를 읽습니다.
12

정지 방식·램프·고장 복귀

인버터의 일반 정지는 설정된 감속 램프를 사용하거나 별도의 정지 방식을 사용할 수 있습니다. 같은 “OFF” 표현이라도 의미가 다를 수 있으므로 해당 모델의 OFF1/OFF2/OFF3와 안전 기능 정의를 확인합니다.

STO 등 안전 기능과 일반 운전 명령 OFF를 혼동하지 않습니다. STO를 포함한 기능의 전기적 격리·잔류 에너지·부하 정지 조건은 별도 안전 매뉴얼로 확인하며, 본 교안은 해당 기능의 구현 절차를 제공하지 않습니다.

교육용 실습에서는 일반 정지 후 관찰한 상태만 기록하고 실제 감속 파라미터·안전 파라미터를 변경하지 않습니다.

확인 문제와 확장 과제

1. PLC에서 정역 명령만 상호 차단하면 충분한가요?

아닙니다. 실제 접촉기 정역 구성에는 적합한 전기적·기계적 인터록, 보호장치와 피드백 감시 등이 필요합니다.

2. 0.5초 기다리면 모터가 멈췄다고 볼 수 있나요?

아닙니다. 이 예제는 별도의 가상 정지 확인과 접촉기 해제를 확인한 상태가 0.5초 유지되는 조건입니다. 실제 정지 보증이 아닙니다.

3. 인버터의 운전 명령과 실제 운전 상태는 같은가요?

아닙니다. 요청과 피드백은 다릅니다. 준비·고장·상태워드·실속도 등을 검토해야 합니다.

4. 27648을 모든 속도 통신 데이터에 쓰면 되나요?

아닙니다. 위 가상 아날로그 스케일에서만 사용하는 예시입니다. 실제 모듈 또는 텔레그램의 정의를 확인합니다.

5. 반대 방향 버튼을 계속 누르면 자동 역회전하나요?

이 예제에서는 아닙니다. 운전을 취소하고 정지 검증 후 대기로 가며, 새 상승 에지가 있어야 시작합니다.

확장 과제

  1. 정역 실습에서 기동 명령 후 해당 피드백이 정해진 시간 내 들어오는지 감시하는 타이머를 추가 설계합니다.
  2. 접촉기 피드백 OFF 지연과 축 정지 지연을 구분해 각각 고장 코드를 부여합니다.
  3. 실습 B의 상태표를 구현하되 실제 제어워드 대신 가상 DriveReady·Running·ActualHz·Fault 입력을 사용합니다.
  4. 속도 설정값의 잘못된 단위·범위 초과·통신 유효성 상실에 대한 정책과 시험표를 작성합니다.

12주차 핵심 정리

  • 운전 요청과 실제 접촉기·드라이브 상태는 다릅니다.
  • 정역 접촉기는 소프트웨어뿐 아니라 적합한 하드웨어 인터록이 필요합니다.
  • 이번 예제는 정지 확인 후 새 시작 입력으로만 방향을 전환합니다.
  • 인버터는 명령·속도 지령과 상태·실속도를 함께 다룹니다.
  • 스케일과 단위는 모듈·텔레그램·드라이브 기준에 맞춰야 합니다.
  • 일반 정지와 안전 기능, 전기적 격리는 서로 구분합니다.
