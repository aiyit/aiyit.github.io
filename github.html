GitHub 사용 매뉴얼

처음 GitHub를 쓰는 분도 순서대로 따라 하면 코드를 올리고, 팀과 함께 작업하고, 웹 페이지로 공개할 수 있도록 정리했습니다. VS Code 화면에서 쓰는 방법은 vsCode.html 문서를 함께 참고하세요.

1. GitHub란?

Git은 내 컴퓨터에서 파일의 변경 이력을 기록하는 프로그램이고, GitHub는 그 기록을 인터넷에 저장하고 여럿이 함께 쓰게 해 주는 서비스입니다. 문서의 "저장 이력"과 "공유 드라이브"를 합친 것으로 생각하면 쉽습니다.

작업 폴더파일 수정
→

→
commit내 컴퓨터에 기록

Repository (저장소)프로젝트 하나를 담는 폴더. 파일과 변경 이력이 함께 저장됨
Commit (커밋)변경 내용을 설명과 함께 기록한 저장 지점

2. 계정 만들기와 보안

  1. github.com에서 Sign up을 누르고 이메일, 비밀번호, 사용자 이름(username)을 입력합니다. 사용자 이름은 주소(github.com/이름)가 되므로 신중하게 정하세요.
  2. 이메일로 온 인증 코드를 입력하면 가입이 끝납니다.
  3. 오른쪽 위 프로필 → Settings → Password and authentication에서 2단계 인증(2FA)을 켭니다. 인증 앱(Google Authenticator 등)을 권장하며, 복구 코드는 따로 보관하세요.
  4. Settings → Profile에서 이름, 소개, 사진을 설정합니다.
이메일 공개가 걱정된다면Settings → Emails에서 Keep my email addresses private를 켜면 커밋 기록에 숨김용 이메일(번호+이름@users.noreply.github.com)이 표시됩니다. Git에 등록하는 이메일도 이 주소로 쓸 수 있습니다.

3. 저장소 만들기

  1. 오른쪽 위 + → New repository를 누릅니다.
  2. Repository name: 영문 소문자와 하이픈 권장 (예: my-web)
  3. Public / Private: Public은 누구나 볼 수 있고, Private은 초대한 사람만 볼 수 있습니다. GitHub Pages 무료 공개는 Public에서 가장 간단합니다.
  4. Add a README file: 체크하면 프로젝트 소개 파일이 함께 생성됩니다. 내 컴퓨터에 이미 폴더가 있다면 체크하지 않는 편이 연결이 쉽습니다.
  5. .gitignore / License: 필요하면 언어(예: Python)와 라이선스(예: MIT)를 선택합니다.
  6. Create repository를 누릅니다.

4. 로그인 방식 (인증)

2021년부터 GitHub는 명령어 사용 시 계정 비밀번호를 받지 않습니다. 아래 세 방법 중 하나를 쓰세요.

방식특징추천 대상
브라우저 로그인push 때 뜨는 창에서 Sign in with your browser 선택. 설정이 가장 쉬움처음 시작하는 분, 실습실
Personal Access Token비밀번호 대신 쓰는 긴 문자열. 만료 기간과 권한을 정할 수 있음스크립트, 자동화
SSH 키내 컴퓨터에 키를 만들어 등록. 한 번 설정하면 로그인 창이 없음자주 쓰는 개인 컴퓨터

SSH 키 설정 (선택)

터미널
ssh-keygen -t ed25519 -C "me@example.com"   # Enter 3번 눌러 기본값 사용
cat ~/.ssh/id_ed25519.pub                    # 출력된 공개 키 전체 복사
ssh -T git@github.com                         # 등록 후 연결 확인

복사한 공개 키(.pub 파일 내용)를 GitHub의 Settings → SSH and GPG keys → New SSH key에 붙여 넣습니다. 이후 저장소 주소는 git@github.com:아이디/저장소.git 형식을 사용합니다.

공용 컴퓨터 주의실습실 같은 공용 PC에서는 로그인 정보가 남지 않도록 작업 후 자격 증명 관리자에서 git:https://github.com을 삭제하고, 비공개 키(id_ed25519, .pub이 없는 파일)는 절대 공유하지 마세요.

5. 기본 작업 흐름

5-1. 처음 한 번만 하는 설정

터미널
git config --global user.name "홍길동"
git config --global user.email "me@example.com"
git config --global init.defaultBranch main
git config --list     # 설정 확인

5-2. 방법 A: 내 컴퓨터의 폴더를 GitHub에 올리기

터미널
cd myweb
git init
git add .
git commit -m "첫 번째 커밋"
git remote add origin https://github.com/아이디/my-web.git
git push -u origin main

5-3. 방법 B: GitHub 저장소를 내려받아 시작하기

터미널
git clone https://github.com/아이디/my-web.git
cd my-web
code .

5-4. 매일 반복하는 작업

  1. 작업 시작 전 최신 내용을 받아옵니다: git pull
  2. 코드를 수정합니다.
  3. 상태 확인: git status (빨간색은 아직 담지 않은 파일, 초록색은 커밋 대기 파일)
  4. 변경 내용 확인: git diff
  5. 담기와 기록: git add . 후 git commit -m "메시지"
  6. 올리기: git push
좋은 커밋 메시지"수정", "ㅇㅇ"보다 "로그인 버튼 색상 변경"처럼 무엇을 바꿨는지 짧게 씁니다. 한 번에 많은 일을 묶지 말고 의미 단위로 자주 커밋하면 나중에 되돌리기 쉽습니다.

5-5. 웹에서 파일 바로 올리기

Git 설치 없이도 저장소의 Add file → Upload files로 파일을 끌어다 놓고 아래쪽 Commit changes를 누르면 올라갑니다. 파일 하나를 고칠 때는 파일을 열어 연필 아이콘으로 편집할 수 있고, 저장소 화면에서 . 키를 누르면 웹 VS Code 편집기가 열립니다.

6. 브랜치와 병합

브랜치는 main(완성본)을 건드리지 않고 새 기능이나 실험을 따로 작업하는 갈래입니다. 작업이 끝나면 main에 합칩니다.

터미널
git branch                    # 브랜치 목록 (현재 브랜치에 * 표시)
git switch -c feature-login   # 새 브랜치를 만들고 이동
# ... 파일 수정, add, commit ...
git push -u origin feature-login   # 브랜치를 GitHub에 올리기 (처음 1회)

git switch main               # main으로 이동
git pull                      # 최신 상태로 갱신
git merge feature-login       # 작업 내용 합치기
git push                      # 합친 결과 올리기
git branch -d feature-login   # 다 쓴 브랜치 삭제

VS Code에서는 왼쪽 아래 상태 표시줄의 브랜치 이름(예: main)을 누르면 목록에서 전환하거나 새로 만들 수 있습니다.

7. Pull Request (PR)

PR은 브랜치의 작업을 main에 합치기 전에 팀원이 검토하는 절차입니다. 혼자 쓰는 저장소에서도 기록을 남기는 용도로 쓸 수 있습니다.

  1. 브랜치를 push하면 저장소 화면에 Compare & pull request 버튼이 나타납니다. 누릅니다.
  2. 제목과 설명에 무엇을, 왜 바꿨는지 적습니다. 오른쪽에서 Reviewers(검토자)를 지정합니다.
  3. Create pull request를 누르면 PR이 열리고, Files changed 탭에서 바뀐 줄을 한눈에 볼 수 있습니다.
  4. 검토자는 줄 옆 +를 눌러 의견을 남기고, Review changes에서 Approve(승인) 또는 Request changes(수정 요청)를 선택합니다.
  5. 승인되면 Merge pull request를 눌러 합칩니다. 합친 뒤에는 Delete branch로 정리합니다.
병합 방식결과
Create a merge commit브랜치의 모든 커밋과 병합 기록이 그대로 남음
Squash and merge여러 커밋을 하나로 합쳐 기록이 깔끔해짐 (수업 과제에 추천)
Rebase and merge커밋을 main 뒤에 일렬로 이어 붙임

8. 충돌 해결

같은 파일의 같은 줄을 두 사람이 다르게 고치면 합칠 때 충돌(conflict)이 생깁니다. 오류가 아니라 "어느 쪽을 쓸지 정해 달라"는 요청입니다.

충돌이 난 파일
<<<<<<< HEAD
<h1>내 컴퓨터의 제목</h1>
=======
<h1>GitHub에 있던 제목</h1>
>>>>>>> origin/main
  1. 충돌 표시(<<<<<<<, =======, >>>>>>>)가 있는 파일을 VS Code로 엽니다. 표시 위에 Accept Current / Accept Incoming / Accept Both 버튼이 나옵니다.
  2. 남길 내용을 선택하거나 직접 고쳐서 표시 줄을 모두 지웁니다.
  3. 저장한 뒤 다음 명령을 실행합니다.
터미널
git add 파일명
git commit -m "충돌 해결"
git push
충돌을 줄이는 습관작업 시작 전 git pull, 작업 후 바로 push, 팀원과 같은 파일을 동시에 고치지 않도록 역할을 나눕니다.

9. Fork와 팀 협업

9-1. 내 저장소에 팀원 초대 (Collaborator)

  1. 저장소 Settings → Collaborators → Add people
  2. 팀원의 GitHub 아이디나 이메일을 입력해 초대합니다.
  3. 팀원이 이메일 또는 알림의 초대를 수락하면 push 권한이 생깁니다.

9-2. 남의 저장소에 기여하기 (Fork 방식)

권한이 없는 저장소는 내 계정으로 복사(Fork)해서 고친 뒤 원본에 PR을 보냅니다.

  1. 원본 저장소 오른쪽 위 Fork를 눌러 내 계정으로 복사합니다.
  2. 내 Fork를 git clone하고 브랜치를 만들어 수정, commit, push합니다.
  3. 내 Fork 화면에서 Contribute → Open pull request로 원본에 요청을 보냅니다.
  4. 원본이 바뀌었다면 Fork 화면의 Sync fork 버튼으로 최신 상태를 가져옵니다.
수업에서 활용하기과제 저장소를 Fork하고 PR로 제출하게 하면, 제출 시각과 수정 이력이 자동으로 기록되고 코드 리뷰까지 한 곳에서 진행할 수 있습니다.

10. Issues와 Projects

Issues는 할 일, 오류, 질문을 기록하는 게시판입니다. Issues → New issue에서 제목과 설명을 쓰고, 오른쪽의 Assignees(담당자), Labels(bug, enhancement 등), Milestone(마감 단위)을 지정합니다.

커밋 메시지나 PR 설명에 fixes #12라고 쓰면 PR이 합쳐질 때 12번 이슈가 자동으로 닫힙니다.

Projects는 이슈를 Todo → In progress → Done 칸으로 옮기며 진행 상황을 보는 칸반 보드입니다. 저장소의 Projects 탭 또는 내 프로필에서 새 프로젝트를 만들어 이슈를 추가하세요.

11. GitHub Pages로 웹 페이지 공개하기

저장소의 HTML, CSS, JS 파일을 무료 웹 주소로 공개하는 기능입니다. 이 문서와 같은 정적 페이지에 알맞습니다.

  1. 저장소 최상위에 index.html을 올립니다.
  2. Settings → Pages를 엽니다.
  3. Source를 Deploy from a branch로 선택하고, Branch는 main, 폴더는 / (root)로 지정한 뒤 Save를 누릅니다.
  4. 1~2분 뒤 같은 화면 위쪽에 공개 주소가 표시됩니다.
저장소 이름공개 주소
아이디.github.io (특별한 이름)https://아이디.github.io/
그 외 모든 이름 (예: my-web)https://아이디.github.io/my-web/
주소 확인할 점파일 이름의 대소문자를 구분합니다. Index.html과 index.html은 다른 파일입니다. 수정 후 반영까지 몇 분 걸리고, 이전 화면이 보이면 Ctrl+F5로 새로 고침하세요. 하위 폴더의 파일은 /폴더명/파일명.html 주소로 접속합니다.

12-2. .gitignore

Git이 추적하지 않을 파일을 정하는 파일입니다. 저장소 최상위에 .gitignore라는 이름으로 만들고 한 줄에 하나씩 씁니다.

.gitignore
node_modules/
__pycache__/
*.exe
*.log
.env
.vscode/
비밀 정보는 절대 올리지 마세요비밀번호, API 키, .env 파일은 Public 저장소에 올리면 누구나 볼 수 있습니다. 실수로 올렸다면 파일을 지우는 것만으로는 부족하며, 이전 기록에 남아 있으므로 해당 키를 즉시 폐기하고 새로 발급받아야 합니다.

13. 되돌리기

상황명령어설명
저장한 수정을 취소 (add 전)git restore 파일명마지막 커밋 상태로 파일을 되돌림. 수정 내용은 사라짐
add를 취소 (commit 전)git restore --staged 파일명파일 내용은 두고 담은 것만 취소
직전 커밋 메시지 고치기 (push 전)git commit --amend -m "새 메시지"이미 push했다면 사용하지 않음
직전 커밋 취소, 수정은 유지 (push 전)git reset --soft HEAD~1커밋만 풀고 변경 내용은 남김
이미 push한 커밋 취소git revert 커밋번호취소한다는 새 커밋을 추가. 기록이 보존되어 안전
되돌릴 수 없는 명령어git reset --hard와 git push --force는 작업 내용이나 팀원의 기록을 지울 수 있습니다. 무엇을 지우는지 확실하지 않다면 사용하지 마세요. 커밋 번호는 git log --oneline에서 확인합니다.

15. 문제 해결 (FAQ)

"fatal: not a git repository"라고 나와요

Git 저장소가 아닌 폴더에 있다는 뜻입니다. pwd로 위치를 확인하고 cd로 프로젝트 폴더로 이동하거나, 새 프로젝트라면 git init을 실행하세요.

push가 "rejected" 또는 "non-fast-forward"로 거절돼요

GitHub에 내 컴퓨터에 없는 새 커밋이 있다는 뜻입니다. git pull로 먼저 받아온 뒤 다시 git push하세요. 충돌이 나면 8장을 따라 해결합니다.

Authentication failed 또는 403 오류가 나요

저장된 이전 계정 정보 때문일 수 있습니다. 윈도우 자격 증명 관리자 → Windows 자격 증명에서 git:https://github.com을 삭제하고 다시 push해 새로 로그인하세요. 저장소 권한(Collaborator 초대 수락 여부)도 확인합니다.

"remote origin already exists"라고 나와요

이미 주소가 등록되어 있습니다. git remote -v로 확인하고, 잘못됐다면 git remote set-url origin 새주소로 바꿉니다.

파일이 GitHub에 안 올라가요

.gitignore에 적힌 파일이 아닌지, git add를 했는지(git status) 확인하세요. 100MB가 넘는 파일은 일반 push가 거절되므로 용량을 줄이거나 Git LFS를 사용해야 합니다.

잘못 만든 저장소를 지우고 싶어요

저장소 Settings 맨 아래 Danger Zone → Delete this repository에서 삭제합니다. 복구할 수 없으니 저장소 이름을 입력하기 전에 한 번 더 확인하세요.
