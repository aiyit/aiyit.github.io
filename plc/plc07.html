SCL 문법과 제어문·반복문

조건 분기와 반복 구조를 이해하고 읽기 쉬운 PLC 프로그램을 작성한다

오늘의 학습 목표

  • SCL 변수, 자료형, 대입문과 비교식을 구분할 수 있다.
  • IF·CASE로 조건에 따른 실행 흐름을 작성할 수 있다.
  • FOR·WHILE·REPEAT의 차이를 설명하고 배열 처리에 적용할 수 있다.
  • PLC 스캔을 고려해 반복문과 상태 제어를 구분할 수 있다.

선수학습: PLC 기본 스캔 및 LD·FBD 기초 / 실습 범위: S7-1200·S7-1500 SCL / 예제는 블록 본문용이며 인터페이스를 먼저 선언합니다.

1

SCL이란? — 문자로 표현하는 PLC 로직

SCL(Structured Control Language)은 Siemens PLC에서 사용하는 구조화된 텍스트 기반 프로그래밍 언어입니다. 접점과 코일을 그리는 LD와 달리, 계산식·조건문·반복문을 문자로 작성합니다. 이 강의는 TIA Portal의 S7-1200 / S7-1500 SCL 블록을 기준으로 합니다.

앞선 LD·FBD 실습에서 다룬 논리를 SCL로 옮겨 보고, 여러 값의 계산과 배열 처리를 간결하게 작성하는 것이 목표입니다.

// 실행 허가와 시작 조건이 모두 참일 때
#RunCmd := #Enable AND #Start;
읽는 방법: “Enable과 Start가 모두 TRUE이면 RunCmd에 TRUE를 대입한다.”
예제의 #은 블록 내부에 선언한 지역 태그를 뜻합니다. PLC 전역 태그는 보통 "StartPB"처럼 큰따옴표로 표시됩니다.
모든 예제는 학습용입니다. 실제 모터·히터 출력에 바로 연결하지 말고, 내부 태그와 시뮬레이션으로 먼저 검증하세요. 비상정지와 안전 기능은 일반 SCL 예제만으로 구현하지 않습니다.
2

변수 선언과 기본 자료형

코드에 쓰는 태그는 먼저 블록 인터페이스에 이름, 자료형, 구분을 선언합니다. 아래 선언은 예제별로 필요한 항목을 골라 사용하세요.

구분의미예시
Input블록이 읽는 입력값Enable : Bool, Temp : Real
Output블록이 계산해 내보내는 결과RunCmd : Bool, Grade : Int
Temp이번 호출에서 쓰는 임시 계산값i : Int, Sum : DInt
Static (FB)호출 사이에 상태를 보관State : Int, PrevStart : Bool
자료형용도예시 리터럴
Bool참/거짓TRUE, FALSE
Int16비트 부호 있는 정수0, 25, -10
DInt32비트 부호 있는 정수DINT#100000
Real실수 계산25.0, 0.5
Time시간값T#2s, T#500ms
Array[0..4] of Int같은 자료형을 묶은 배열Values[0] ~ Values[4]
Temp 변수는 이전 스캔의 값을 저장하는 용도로 쓰지 않습니다. 읽기 전에 반드시 값을 대입하세요. FB Static이 호출 사이 상태를 보관한다는 것과 전원 차단 후에도 유지하는 리테인(Retain) 설정은 서로 다릅니다.

기본 문법과 연산자

(* 여러 줄에 걸쳐
   설명하는 주석 *)
#Count := 10;                 // 대입
#NextCount := #Count + 1;     // 산술 계산
#IsTarget := (#Count = 10);   // 같은지 비교
#Allowed := #Enable AND NOT #Fault;

산술+, -, *, /, MOD사칙연산과 정수 나머지

대입 :=과 비교 =를 구분하세요. 조건식에는 괄호를 사용해 의도를 명확히 표현하고, 정수/실수 혼합 계산에서는 명시적인 자료형 변환을 권장합니다.
// Count : Int, Ratio : Real
#Ratio := INT_TO_REAL(#Count) / 100.0;
4

IF · ELSIF · ELSE — 조건에 따라 실행

IF는 위에서부터 조건을 검사해 처음 TRUE가 된 분기 하나를 실행합니다. ELSIF와 ELSE는 필요한 경우에만 작성합니다.

// Temp : Real (Input), Level : Int (Output)
IF #Temp >= 80.0 THEN
    #Level := 2;      // 고온
ELSIF #Temp >= 50.0 THEN
    #Level := 1;      // 주의
ELSE
    #Level := 0;      // 정상
END_IF;
Temp실행 분기Level
35.0ELSE0
50.0ELSIF1
80.0첫 번째 IF2

80.0은 두 비교 조건을 모두 만족하지만, 위쪽 분기가 먼저 선택되므로 Level은 2가 됩니다.

// 매 호출마다 결과를 확실하게 결정하는 패턴
#RunCmd := FALSE;
IF #Enable AND NOT #Fault THEN
    #RunCmd := TRUE;
END_IF;
어떤 경로에서도 출력에 값을 쓰지 않으면 이전 값이 남을 수 있습니다. 의도적인 상태 저장이 아니라면 기본값 또는 ELSE 분기로 결과를 명확하게 정의하세요.
5

CASE — 모드별 다중 분기

하나의 정수형 값으로 여러 동작 중 하나를 선택할 때 CASE를 사용하면 조건이 명확해집니다. 선택된 분기만 실행하며, 일치하는 값이 없으면 ELSE를 실행합니다.

// Mode : Int (Input), SpeedRef : Real (Output)
CASE #Mode OF
    0:
        #SpeedRef := 0.0;      // 정지
    1:
        #SpeedRef := 20.0;     // 저속
    2:
        #SpeedRef := 50.0;     // 고속
    3, 4:
        #SpeedRef := 10.0;     // 점검 모드
    ELSE
        #SpeedRef := 0.0;      // 정의되지 않은 모드
END_CASE;
IF는 범위·복합 조건에, CASE는 모드 번호·단계 번호처럼 한 값에 따른 선택에 적합합니다. CASE는 C 언어의 switch와 달리 다음 분기로 자동으로 흘러가지 않으므로 분기마다 break를 넣지 않습니다.
6

FOR — 횟수가 정해진 반복

FOR는 시작값부터 종료값까지 카운터를 바꾸며 반복합니다. BY를 생략하면 1씩 증가합니다. 배열 전체 합산처럼 범위가 명확한 작업에 사용합니다.

// Values : Array[0..4] of Int (Input)
// Sum : DInt (Output), i : Int (Temp)
#Sum := 0;
FOR #i := 0 TO 4 DO
    #Sum := #Sum + INT_TO_DINT(#Values[#i]);
END_FOR;

Values가 [10, 20, 30, 40, 50]이면 반복은 5회 실행되고 Sum은 150입니다.

// 역순 처리: 4, 3, 2, 1, 0
FOR #i := 4 TO 0 BY -1 DO
    #Buffer[#i] := 0;
END_FOR;
Buffer는 Array[0..4] of Int인 Output 또는 InOut 태그로 별도 선언합니다. 배열 범위를 넘지 않도록 시작값·종료값을 맞추고, 카운터 자료형의 한계값에 가까운 반복 범위나 0인 증가값은 피하세요.
7

WHILE · REPEAT — 조건으로 반복

WHILE: 실행하기 전에 조건 검사

조건이 TRUE인 동안 반복합니다. 처음부터 FALSE이면 본문을 한 번도 실행하지 않습니다.

// N : Int (Input, 실습값 0~10)
// Count : Int (Output), i : Int (Temp)
#i := 0;
#Count := 0;
WHILE (#i < #N) AND (#i < 10) DO
    #Count := #Count + 1;
    #i := #i + 1;
END_WHILE;

REPEAT: 한 번 실행한 뒤 종료 조건 검사

UNTIL 뒤의 조건이 TRUE이면 종료합니다. 본문은 최소 한 번 실행됩니다.

#i := 0;
#Count := 0;
REPEAT
    #Count := #Count + 1;
    #i := #i + 1;
UNTIL (#i >= #N) OR (#i >= 10)
END_REPEAT;
항목WHILE 예제REPEAT 예제
N = 00회1회
N = 33회3회
검사 시점본문 실행 전본문 실행 후
조건 의미TRUE이면 계속TRUE이면 종료
반복 조건에 영향을 주는 값을 본문에서 갱신하고, 최대 반복 횟수도 제한하세요. 바뀌지 않는 TRUE 조건은 끝나지 않는 반복을 만들 수 있습니다.
8

EXIT · CONTINUE — 반복 흐름 조절

EXIT는 현재의 가장 안쪽 반복문을 즉시 빠져나옵니다. CONTINUE는 현재 회차의 나머지 코드를 건너뛰고 다음 반복 판단으로 이동합니다.

// Values : Array[0..4] of Int (Input)
// FoundIndex : Int (Output), i : Int (Temp)
#FoundIndex := -1;
FOR #i := 0 TO 4 DO
    IF #Values[#i] < 0 THEN
        CONTINUE;              // 음수는 검색에서 제외
    END_IF;
    IF #Values[#i] >= 100 THEN
        #FoundIndex := #i;
        EXIT;                  // 첫 번째 일치 항목에서 종료
    END_IF;
END_FOR;

입력값이 [-5, 20, 120, 150, 30]이면 FoundIndex는 2입니다. 배열 인덱스는 이 예제에서 0부터 시작합니다. 일치 항목이 없으면 -1을 유지합니다.

WHILE에서 CONTINUE를 쓰면 카운터 갱신 코드를 건너뛸 수 있습니다. 갱신 위치에 따라 무한 반복이 생길 수 있으므로 초보 실습에서는 FOR부터 익히세요.
9

PLC 스캔과 반복문 — 기다리는 코드를 만들지 않기

반복문은 기본적으로 현재 블록 호출 안에서 연속 실행됩니다. FOR를 10번 반복한다고 PLC 스캔이 10번 진행되거나 10초가 지나는 것이 아닙니다. 반복량이 많으면 사이클 시간이 길어질 수 있습니다.

블록 호출→반복문 전체 실행→다음 명령→호출 종료
// 작성하면 안 되는 대기 방식의 개념 예시
// WHILE NOT #Sensor DO
//     센서가 바뀔 때까지 이 자리에 머무름
// END_WHILE;

일반적인 프로세스 이미지 입력이 반복 중 알아서 다음 스캔 값으로 갱신된다고 기대해서는 안 됩니다. 센서 대기는 매 스캔 조건을 확인하는 상태 변수로 구성하고, 시간 대기는 적절한 타이머를 사용합니다.

데이터 여러 개를 지금 계산한다 → 반복문
센서·시간 조건을 여러 스캔에 걸쳐 기다린다 → 상태 전이 + 타이머
대용량 데이터 → 스캔당 처리량을 제한해 분할 처리

CPU는 사이클 시간 감시 기능을 제공합니다. 실제 허용 실행 시간과 오류 반응은 CPU 및 프로젝트 설정을 확인하세요.

종합 예제 — CASE로 단계 제어하기

FB를 만들고 아래 인터페이스를 선언합니다. State와 PrevStart는 Static으로 선언하고 시작값을 각각 0과 FALSE로 설정합니다. FB는 주기 프로그램에서 매 스캔 호출합니다.

구분이름자료형·설명
InputStart, Reset, Sensor각각 Bool
OutputRunCmd, Done각각 Bool
StaticStateInt, 시작값 0
StaticPrevStartBool, 시작값 FALSE
TempStartEdgeBool
// 시작 신호의 상승 에지 검출
#StartEdge := #Start AND NOT #PrevStart;
#PrevStart := #Start;

// Reset이 단계 전이보다 우선
IF #Reset THEN
    #State := 0;
ELSE
    CASE #State OF
        0: // 대기
            IF #StartEdge AND NOT #Sensor THEN
                #State := 10;
            END_IF;
        10: // 가동, 다음 스캔에서도 센서 확인
            IF #Sensor THEN
                #State := 20;
            END_IF;
        20: // 완료, Reset까지 유지
            #State := 20;
        ELSE
            #State := 0;
    END_CASE;
END_IF;

// 전이 이후 상태로 출력을 계산
#RunCmd := (#State = 10);
#Done := (#State = 20);
0: 대기→10: 가동→20: 완료

Start의 FALSE→TRUE 변화가 들어오고 Sensor가 FALSE이면 가동합니다. Sensor가 TRUE이면 완료 상태로 바뀌며 RunCmd는 FALSE, Done은 TRUE가 됩니다. Reset은 어느 단계에서나 대기로 돌려보냅니다.

이 예제에는 운전 시간 초과 감시, 고장 처리, 안전 인터록이 포함되어 있지 않습니다. 실제 설비용 완성 로직이 아닙니다. Reset 동안 Start를 계속 누르고 있으면 해제만으로 재시작하지 않으며, 새 상승 에지가 필요합니다.

추가 과제: 합계·평균·최댓값

Values : Array[0..4] of Int에 [12, 7, 25, 10, 6]을 넣고 FOR로 합계, 평균, 최댓값을 구하세요. Sum : DInt, Average : Real, MaxValue : Int를 Output에, i : Int를 Temp에 선언합니다.

정답 코드와 예상 결과 보기
#Sum := 0;
#MaxValue := #Values[0];
FOR #i := 0 TO 4 DO
    #Sum := #Sum + INT_TO_DINT(#Values[#i]);
    IF #Values[#i] > #MaxValue THEN
        #MaxValue := #Values[#i];
    END_IF;
END_FOR;
#Average := DINT_TO_REAL(#Sum) / 5.0;

합계 60, 평균 12.0, 최댓값 25입니다. 최댓값은 0이 아니라 첫 번째 원소로 초기화해야 입력이 모두 음수여도 바르게 계산합니다.

12

확인 문제와 자주 발생하는 오류

1. #Count := 5와 #Count = 5의 차이는?

:=는 대입이고 =는 비교입니다. 전자는 Count에 5를 저장하며, 후자는 같은지를 판단하는 식입니다.

2. FOR #i := 0 TO 4 DO는 몇 회 실행되나요?

0, 1, 2, 3, 4의 총 5회입니다. BY 생략 시 증가값은 1입니다.

3. 최초 조건이 FALSE인 WHILE과 종료 조건이 TRUE인 REPEAT의 차이는?

WHILE 본문은 0회, REPEAT 본문은 최소 1회 실행됩니다.

4. 왜 센서가 켜질 때까지 WHILE로 기다리면 안 되나요?

블록 실행을 붙잡아 사이클 시간을 늘리거나 끝나지 않을 수 있습니다. 매 스캔 호출되는 상태 제어로 센서를 확인해야 합니다.

증상확인할 점
컴파일 오류THEN, DO, END_IF;, END_FOR; 및 태그 선언 확인
배열 접근 오류선언된 하한·상한과 반복 범위 확인
누적값이 예상보다 계속 증가합계 초기화 위치와 호출 주기 확인
소수 결과가 의도와 다름정수/실수 자료형과 명시 변환 확인
이전 출력이 남음모든 분기에서 값이 정의되는지 확인

가상 배열 실습 — FOR 본문을 한 회씩 추적

Int 값 다섯 개를 입력하고 합계·최댓값을 계산하는 각 반복 회차를 확인합니다. 이 모형은 정해진 예제만 수행하며 임의의 SCL 코드를 실행·컴파일하는 도구가 아닙니다.

// Values : Array[0..4] of Int (Input)
// Sum : DInt, MaxValue : Int (Output)
// i : Int (Temp)
#Sum := 0;
#MaxValue := #Values[0];
FOR #i := 0 TO 4 DO
    #Sum := #Sum + INT_TO_DINT(#Values[#i]);
    IF #Values[#i] > #MaxValue THEN
        #MaxValue := #Values[#i];
    END_IF;
END_FOR;

초기값을 준비했습니다. 입력을 바꾸었다면 먼저 적용하세요.

처리한 원소 0/5 · 다음 배열 인덱스 0 Sum=0 / MaxValue=12 / 평균=아직 계산 전

    화면의 “다음 배열 인덱스”는 모형의 진행 표시입니다. 실제 SCL의 루프 종료 후 카운터 값에 대한 설명이 아닙니다. 반복 버튼 다섯 번이 실제 PLC 스캔 다섯 번을 뜻하지 않습니다. 실제 FOR 본문은 같은 블록 호출 안에서 이어서 실행됩니다.

    입력합계최댓값평균
    12, 7, 25, 10, 6602512.0
    -8, -3, -12, -5, -10-38-3-7.6
    0, 0, 0, 0, 0000.0
    32767, 32767, 32767, 32767, 327671638353276732767.0
    Int 다섯 개의 합계는 Int 범위를 넘을 수 있어 DInt로 누적합니다. 최댓값의 초기값은 0이 아닌 첫 원소로 둡니다. 그래야 모든 원소가 음수여도 결과가 맞습니다.

    경계값·호출·초기화 검토와 제출 과제

    반복문과 계산의 점검

    • 배열 하한·상한을 실제 선언과 일치시켰는가?
    • FOR 카운터·시작값·끝값·증가값의 자료형과 범위를 확인했는가?
    • WHILE·REPEAT의 조건이 반드시 바뀌고 최대 반복량이 제한되는가?
    • CONTINUE 때문에 조건 갱신 코드를 건너뛰지 않는가?
    • 누적 변수는 의도한 호출 단위에서 초기화하는가?
    • 실수 결과가 필요하면 나눗셈 전에 자료형을 변환하는가?

    CASE 상태 제어의 점검

    상태는 FB Static 등 호출 간 유지되는 공간에 두고 매 스캔 블록을 호출합니다. Reset, Stop, 고장, 정상 전이의 우선순위를 먼저 정의합니다. 예제에서 사용한 State의 호출 간 유지와 전원 차단 후 Retain은 서로 다릅니다.

    센서가 변하기를 반복문 안에서 기다리지 않습니다. 여러 스캔에 걸친 대기는 상태 전이·타이머로 설계하고 매 호출에 조건을 확인합니다.
    앞의 CASE 종합 예제는 교육용 순서만 보여 줍니다. 시간 초과·고장·실제 위치 확인·전원 복귀 재무장·안전 기능이 완성된 프로그램이 아닙니다. 최초 호출에 Start가 TRUE이고 PrevStart가 FALSE이면 단순 상승 에지로 인식할 수 있으므로, 실제 요구가 다르면 초기 해제 확인을 설계합니다.

    제출 과제

    1. IF·CASE·FOR·WHILE·REPEAT의 선택 기준을 한 문장씩 정리합니다.
    2. 입력 다섯 개의 합계·최댓값·평균을 구하는 인터페이스 표와 코드를 작성합니다.
    3. 양수·음수·0·Int 경계값으로 예상값과 관찰값을 기록합니다.
    4. 한 블록 호출 안의 반복과 여러 스캔에 걸친 단계 제어의 차이를 설명합니다.
    5. 선택 실습을 수행했다면 CPU·펌웨어·TIA Portal 버전, 컴파일 결과와 미실행 항목을 기록합니다.

    다음 주: SFC를 이용한 시퀀스 설계

    이번 주의 CASE 기반 상태 제어를 단계·전이·동작 도식으로 정리합니다. 정상 순서뿐 아니라 인터록·시간 초과·정지·복귀를 함께 설계합니다.

    7주차 핵심 정리

    • 대입은 :=, 비교는 =, 문장 마침은 세미콜론입니다.
    • IF는 조건 판단, CASE는 값에 따른 분기에 사용합니다.
    • FOR는 범위 반복, WHILE은 선검사, REPEAT는 후검사 반복입니다.
    • 반복문은 현재 호출 안에서 처리됩니다. 시간·센서 대기는 상태와 타이머로 구성합니다.
    • 변수 초기화, 배열 범위, 종료 조건을 반드시 확인합니다.

    공식 문서 및 적용 범위

    제어문 문법과 사이클 시간 개념은 Siemens 공식 문서를 참고했습니다. 예제·배열 모형·실습 데이터는 교육용 구성입니다. 실제 CPU·펌웨어·TIA Portal 버전에 따라 지원 범위를 확인하세요. 파일 구조·내부 링크·배열 계산·상태 전이의 가상 모델은 점검했으나 실제 TIA Portal 컴파일·PLCSIM 실행·브라우저 렌더링 및 클릭 자동 시험은 수행하지 않았습니다. 가상 배열 모형은 SCL 컴파일러가 아니며 실제 PLC의 실행 시간을 재현하지 않습니다.
