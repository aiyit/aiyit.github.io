13주차 · Module 13

타이머·카운터·연산·비교 명령 고급

시간·이벤트·수치의 경계 조건을 고려한 신뢰성 있는 로직을 설계한다

오늘의 학습 목표

  • IEC 타이머·카운터의 상태와 에지 동작을 구분한다.
  • 필터와 재무장으로 유효한 제품 이벤트를 정의한다.
  • 0 나눗셈·자료형·오버플로를 고려해 계산한다.
  • 범위·허용오차·히스테리시스 비교를 구분한다.
  • 종합 FB를 작성하고 정상·경계·오류 시나리오를 시험한다.

선수학습: SCL·FB·타이머·11~12주차 실습 / 대상: TIA Portal S7-1200·S7-1500 지원 환경 / 내부 DB 기반 가상 실습 / 실제 I/O·고속 계수·안전 기능 제외

1

이번 주의 핵심 — 명령보다 실행 조건

타이머·카운터·연산·비교 명령은 단순해 보이지만 호출 주기, 신호 에지, 초기화, 자료형과 경계값에 따라 결과가 달라집니다. 이번 수업에서는 명령을 나열하는 대신 “어떤 값을 언제 계산하고 언제 유지할 것인가”를 기준으로 설계합니다.

입력 유효성→시간·이벤트 처리→계산→비교·판정→상태·결과 표시

7주차 SCL 문법과 11·12주차의 타이머·상태 제어를 확장하여, 가상 제품 센서를 필터링하고 배치 수량과 처리율을 계산하는 FB를 작성합니다.

모든 예제는 내부 DB 태그를 사용하는 교육용입니다. 실제 출력·고속 계수 입력·안전 기능에 연결하지 않습니다. 타이머 인스턴스는 편집기에서 생성하고 CPU·TIA Portal 버전의 지원 조건을 확인합니다.
2

타이머 비교 — TON · TOF · TP · TONR

명령핵심 동작사용 예·주의
TONIN이 TRUE로 PT 동안 유지되면 Q=TRUE입력 안정 확인. IN=FALSE이면 일반적으로 Q·ET 초기화
TOFIN이 FALSE가 된 후 PT 동안 Q 유지일반적인 지연 소등. 안전 정지 지연에 임의 적용 금지
TPIN 상승 에지로 PT 길이의 펄스 발생일정 시간 표시. 펄스 중 새 입력을 무조건 재트리거로 기대하지 않음
TONR조건에 따라 경과 시간을 누적하는 유지형 지연별도 리셋·상태 초기화 요구 확인

IEC 타이머의 주요 파라미터는 IN(조건), PT(설정 시간), Q(결과), ET(경과 시간)입니다. 명령별 추가 파라미터와 재시작 조건은 매뉴얼을 확인합니다. TONR의 시간 누적 의미와 전원 차단 후 Retain 유지 여부는 별개입니다.

TON의 Q는 단순한 “시간이 한 번 지났다” 기록이 아닙니다. IN이 FALSE가 되면 완료 상태도 해제됩니다. 완료를 저장하려면 별도의 상태·래치 정책이 필요합니다.
3

TON 시간표와 호출 규칙

TON의 PT=T#2s를 가정합니다. 아래 시간은 개념적인 경과 시간이며 실제 관찰에는 호출 주기가 반영됩니다.

상황INET·Q
초기 상태FALSEET=0, Q=FALSE
입력이 켜진 직후TRUEET 증가 시작, Q=FALSE
2초 이전TRUEET<PT, Q=FALSE
2초 이상 유지TRUEQ=TRUE
입력 해제FALSEQ=FALSE, ET 초기화
// HoldTimer: FB Static의 TON 멀티인스턴스
#HoldTimer.TON(IN := #Condition AND NOT #Reset, PT := T#2s);
#Stable := #HoldTimer.Q;
#Elapsed := #HoldTimer.ET;
타이머를 IF 조건 안에서 일부 스캔만 호출하는 대신 매 스캔 호출하고 IN으로 조건을 제어합니다. 같은 인스턴스를 서로 다른 용도로 여러 번 호출하지 않으며, 내부 타이머 구조를 임의로 덮어쓰지 않습니다.

주기 프로그램은 정확한 실시간 오실로스코프가 아닙니다. 짧은 펄스가 스캔 사이에 발생하면 소프트웨어가 놓칠 수 있습니다. 빠른 신호는 지원되는 하드웨어 입력·필터·고속 카운터 또는 이벤트 처리를 별도로 검토합니다.

4

카운터 — 상태가 아니라 에지를 세기

명령역할주요 파라미터
CTU상승 에지마다 증가CU, R, PV, Q, CV
CTD상승 에지마다 감소CD, LD, PV, Q, CV
CTUD증가·감소를 함께 처리CU, CD, R, LD, PV, QU/QD, CV

CTU는 CU가 FALSE→TRUE로 바뀔 때 계수합니다. CU가 TRUE인 채 여러 스캔 유지된다고 매 스캔 증가하는 것은 아닙니다. 보통 CV가 PV 이상이면 Q가 TRUE가 되지만, Q는 목표값에서 CV를 자동으로 멈추는 명령이 아닙니다.

// BatchCounter: DInt 계수형으로 만든 CTU 멀티인스턴스 예시
// PV와 CV의 자료형도 선택한 카운터 형식에 맞춤
#BatchCounter.CTU(CU := #QualifiedSensor,
                  R := #Reset,
                  PV := DINT#10,
                  Q => #TargetReached,
                  CV => #Count);
구체적인 카운터 형식 이름·호출 구문은 편집기가 생성한 것을 사용합니다. 리셋 R, 로드 LD와 계수 입력이 동시에 들어올 때의 우선순위도 명령 설명에서 확인합니다. CTU 자체 에지 검출과 별도 R_TRIG를 불필요하게 중첩하지 않습니다.
5

한 제품을 여러 번 세는 문제 — 필터와 재무장

센서가 튀면 한 제품이 여러 상승 에지로 보일 수 있습니다. ON 지연만 넣으면 짧은 OFF 후 다시 ON되는 경우를 완전히 막지 못할 수 있으므로, 재계수하려면 OFF도 일정 시간 유지되도록 설계할 수 있습니다.

  1. 센서가 FALSE로 100ms 유지되면 Armed=TRUE로 재무장합니다.
  2. 그 후 TRUE로 50ms 유지되면 제품 이벤트를 한 번 만듭니다.
  3. 계수 후 Armed=FALSE로 바꾸어 ON 유지 중 재계수를 막습니다.
  4. 다음 제품을 세려면 다시 FALSE 100ms가 필요합니다.
이 방식은 센서 펄스가 충분히 느린 가상 공정의 예입니다. 50ms·100ms는 임의의 교육 값이며 실제 센서의 최소 ON/OFF 시간에 맞춰야 합니다.

최소 OFF 시간이 실제 제품 간격보다 길면 정상 제품도 누락됩니다. 소프트웨어 필터는 신호 문제를 무조건 해결하는 기능이 아니라 유효 신호의 시간 조건을 명시하는 설계입니다.

6

산술 연산과 자료형 — 계산 전에 범위 확인

항목위험개선
정수 곱셈결과 저장형이 커도 중간 결과가 넘칠 수 있음연산 전에 충분히 넓은 형식으로 변환
정수 나눗셈실수 결과를 기대했지만 소수부 손실나누기 전에 Real 등으로 변환
형 변환잘림·반올림·범위 초과함수별 규칙과 유효 범위 확인
0으로 나누기정상 결과가 정의되지 않음나눗셈 실행 전에 분모 검사
카운트 누적자료형 상한 초과포화·오류·리셋 정책 명시
// A, B : Int / Product : DInt
#Product := INT_TO_DINT(#A) * INT_TO_DINT(#B);

// Count : DInt / Seconds, Rate : Real / RateValid : Bool
#Rate := 0.0;
#RateValid := FALSE;
IF #Seconds > 0.0 THEN
    #Rate := DINT_TO_REAL(#Count) / #Seconds;
    #RateValid := TRUE;
END_IF;
이 예제는 유한한 정상 Real 입력을 전제로 합니다. NaN·무한대·센서 오류·통신 유효성 상실은 별도 검증해야 합니다. Real 변환은 임의 크기의 정수를 항상 정확하게 보존하지 않습니다.
7

비교·범위 판정·허용오차

// 입력값과 한계값은 유한한 정상 Real이라고 가정
#InRange := (#Value >= #LowLimit) AND (#Value <= #HighLimit);
#NearTarget := ABS(#Value - #Target) <= #Tolerance;
검토 사항설계 규칙
범위 포함 여부>와 >=, <와 <=를 요구사항대로 선택
설정 오류LowLimit > HighLimit이면 유효하지 않음
허용오차Tolerance는 0 이상이어야 함
실수 비교측정값에 정확한 = 비교 대신 적절한 오차 범위 검토
입력 품질오류·단선·통신 무효 값은 정상 범위 판정에서 제외

비교 연산은 물리적 단위를 모릅니다. 10.0이 Hz인지 rpm인지 °C인지 태그명과 인터페이스 문서에 적고 같은 단위끼리 비교합니다.

아래 종합 실습의 입력 값은 제한된 가상 범위로 검증합니다. 일반 프로그램에서 모든 Real 값에 이 단순 검사만 적용해도 충분하다고 가정하지 마세요.
8

히스테리시스 — 경계에서 상태가 떨리지 않게

온도가 경계 근처에서 흔들릴 때 단일 비교만 사용하면 경보가 빠르게 켜졌다 꺼질 수 있습니다. 서로 다른 ON·OFF 경계를 사용하여 현재 상태를 유지하는 구간을 둡니다.

// AlarmMemory : Bool (Static)
// 유한한 Temp와 유효한 설정: OffThreshold < OnThreshold
IF #Reset THEN
    #AlarmMemory := FALSE;
ELSIF #Temp >= #OnThreshold THEN
    #AlarmMemory := TRUE;
ELSIF #Temp <= #OffThreshold THEN
    #AlarmMemory := FALSE;
END_IF;
#Alarm := #AlarmMemory;
온도 예시ON=80.0 / OFF=75.0에서의 결과
74.0OFF
80.0ON
78.0직전 ON 유지
75.0OFF
77.0직전 OFF 유지
허용오차는 값이 목표 근처인지 판단하는 범위이고, 히스테리시스는 현재 상태에 따라 전환 경계를 다르게 하는 기억 동작입니다.

설정 오류·센서 무효·Reset 중 출력 정책을 별도로 정합니다. 위 코드는 Reset 동안 경보를 끄므로 안전 또는 실제 공정 경보에 그대로 적용하지 않습니다.

9

종합 실습 — 가상 제품 배치와 처리율

제품 센서의 ON/OFF 안정 시간을 확인해 배치를 계수합니다. 목표 수량에 도달하면 완료를 저장하고 더 세지 않습니다. Enable은 일시정지로 사용하지 않습니다. 운전 중 Enable이 FALSE가 되면 해당 배치를 취소하고 Reset 전까지 다시 시작하지 않습니다.

구분태그자료형·규칙
InputEnable, Reset, Sensor각각 Bool
InputTargetDInt, 1~1000000 허용
InputRunSecondsReal, 0~86400 범위의 가상 경과 시간
OutputCountDInt
OutputDone, Aborted, ConfigFault각각 Bool
OutputRateValidBool
OutputRatePerMinuteReal
StaticCountMem, TargetLatched각각 DInt, 0
StaticArmed, DoneMem, Active, AbortMem각각 Bool, FALSE
StaticOnFilter, OffFilter각각 TON 멀티인스턴스
TempTargetOK, TimeOK, WorkAllowed각각 Bool

FB FB_BatchAdvanced와 인스턴스 DB를 생성합니다. 전역 DB LabAdvanced에 Input·Output 태그를 만들어 주기 프로그램에서 연결합니다. RunSeconds는 외부에서 주는 모의 값이며 FB가 실제 운전 시간을 자동 측정하는 것은 아닙니다.

Target은 배치 시작 시 TargetLatched에 저장합니다. 운전 중 설정이 바뀌면 ConfigFault를 표시하고 배치를 취소합니다. Reset은 Enable=FALSE일 때만 받아들이도록 설계했습니다.
10

종합 실습 전체 코드 — FB 본문

// 1. 가상 입력 검증: 유한한 정상 Real 입력을 전제로 함
#TargetOK := (#Target >= DINT#1) AND (#Target <= DINT#1000000);
#TimeOK := (#RunSeconds >= 0.0) AND (#RunSeconds <= 86400.0);
#ConfigFault := NOT #TargetOK;
IF #Active AND (#Target <> #TargetLatched) THEN
    #ConfigFault := TRUE;
END_IF;

// 2. 정지한 상태에서만 Reset 허용
IF #Reset AND NOT #Enable THEN
    #CountMem := 0;
    #TargetLatched := 0;
    #Armed := FALSE;
    #DoneMem := FALSE;
    #Active := FALSE;
    #AbortMem := FALSE;
ELSE
    IF #Active AND NOT #DoneMem AND
       (NOT #Enable OR #ConfigFault) THEN
        #AbortMem := TRUE;
    END_IF;
    IF #Enable AND NOT #Reset AND NOT #Active AND
       NOT #DoneMem AND NOT #AbortMem AND NOT #ConfigFault THEN
        #TargetLatched := #Target;
        #Active := TRUE;
    END_IF;
END_IF;

#WorkAllowed := #Active AND #Enable AND NOT #Reset
                AND NOT #DoneMem AND NOT #AbortMem AND NOT #ConfigFault;

// 3. ON/OFF 필터는 서로 다른 인스턴스로 매 스캔 호출
#OnFilter.TON(IN := #WorkAllowed AND #Sensor, PT := T#50ms);
#OffFilter.TON(IN := #WorkAllowed AND NOT #Sensor, PT := T#100ms);

IF NOT #WorkAllowed THEN
    #Armed := FALSE;
ELSE
    IF #OffFilter.Q THEN
        #Armed := TRUE;
    END_IF;
    IF #OnFilter.Q AND #Armed THEN
        #Armed := FALSE;
        // Target은 최대 1000000이므로 DInt 범위 내에서 증가
        IF #CountMem < #TargetLatched THEN
            #CountMem := #CountMem + 1;
        END_IF;
        IF #CountMem >= #TargetLatched THEN
            #DoneMem := TRUE;
        END_IF;
    END_IF;
END_IF;

// 4. 결과와 처리율: 유효하지 않으면 숫자와 유효성 함께 초기화
#Count := #CountMem;
#Done := #DoneMem;
#Aborted := #AbortMem;
#RatePerMinute := 0.0;
#RateValid := FALSE;
IF #Active AND NOT #Reset AND NOT #AbortMem AND NOT #ConfigFault
   AND #TimeOK AND (#RunSeconds > 0.0) THEN
    #RatePerMinute := DINT_TO_REAL(#CountMem) * 60.0 / #RunSeconds;
    #RateValid := TRUE;
END_IF;

읽어야 할 동작 특성

  • 운전 시작 시 Sensor가 이미 TRUE이면 세지 않습니다. 먼저 FALSE 100ms로 재무장해야 합니다.
  • 센서를 TRUE로 계속 유지해도 한 번만 셉니다.
  • 일반 계수 부분은 CTU 대신 직접 증가문을 사용합니다. 필터·Armed가 한 이벤트만 만들어 주며 목표에서 포화합니다.
  • 완료 후 Count·Done은 유지됩니다. 새 배치는 Enable=FALSE에서 Reset한 뒤 시작합니다.
  • 완료 전에 Enable을 끄면 Aborted가 저장되고 단순 재활성화로 이어 세지 않습니다.
  • RunSeconds는 외부 모의 값입니다. 완료 후에도 값을 바꾸면 처리율은 달라집니다. 완료 시점 값을 고정하는 기능은 확장 과제입니다.
ConfigFault는 현재 설정 이상 표시이고 Aborted는 취소 기록입니다. 설정을 복구해 ConfigFault가 사라져도 Aborted는 Reset 전까지 유지됩니다. Reset 중 Sensor 상태와 관계없이 필터·Armed는 초기화됩니다.

짧은 OFF 시험 뒤에는 반드시 충분한 OFF를 주어 다음 유효 이벤트를 만듭니다. 감시 테이블로 30ms를 정확히 조작하기 어려우면 별도 가상 펄스 발생기나 시뮬레이션 시험 로직을 쓰고 실제 발생 시간을 기록합니다. 사람의 클릭 간격을 정밀 시간 시험으로 간주하지 않습니다.

14

확인 문제와 확장 과제

1. TONR은 전원 차단 후에도 반드시 시간을 유지하나요?

아닙니다. 시간 누적 동작과 전원 차단 후 데이터 유지 정책은 다릅니다. CPU·인스턴스·Retain 및 초기화 조건을 별도로 확인합니다.

2. CTU의 CU가 1초 TRUE이면 몇 번 증가하나요?

한 번의 FALSE→TRUE 에지라면 한 번입니다. TRUE 유지 시간을 스캔 수만큼 계수하지 않습니다.

3. CTU의 Q가 TRUE이면 CV가 자동으로 멈추나요?

목표 비교 결과와 계수 차단은 다릅니다. 목표에서 멈추려면 추가 계수 허가·포화 정책을 설계합니다.

4. Int 곱셈 결과를 DInt에 저장하면 중간 오버플로가 항상 방지되나요?

아닙니다. 연산 전에 피연산자를 충분한 범위의 자료형으로 변환하는 등 평가 형식을 확인해야 합니다.

5. 히스테리시스 구간의 출력은 어떻게 정해지나요?

ON/OFF 경계 사이에서는 직전 상태를 유지합니다. 따라서 상태 메모리가 필요합니다.

확장 과제

  1. RunSeconds를 외부 값 대신 명확한 시간 기준으로 측정합니다. 주기 OB 사용 또는 시간 차 계산 방식을 선정하고 오차·범위·재시작 정책을 설명합니다.
  2. 완료 순간 처리율과 시간을 별도 출력에 저장해 완료 후 입력 변화의 영향을 없앱니다.
  3. 센서 ON 고착·OFF 고착 감시를 추가하고 단순 무제품 대기와 고장을 구분합니다.
  4. 일반 CTU 버전과 Armed 기반 포화 계수 버전을 비교해 목표 이후 동작을 기록합니다.
  5. 히스테리시스 설정 유효성 및 입력 품질 검사를 포함한 별도 FB를 작성합니다.
