1. 객체지향 프로그래밍(OOP)이란?

객체지향 프로그래밍(Object-Oriented Programming)은 데이터와 데이터를 처리하는 기능을 하나의 객체 단위로 묶어 프로그램을 설계하는 방법입니다.

핵심 암기 : 객체는 속성(Attribute)과 메서드(Method)로 구성됩니다. 클래스는 객체를 생성하기 위한 설계도입니다.
용어의미Python 예시
클래스(Class)객체를 만들기 위한 설계도class Student:
객체(Object)클래스를 바탕으로 만들어진 실체student = Student()
인스턴스(Instance)특정 클래스에 의해 생성된 객체student
속성(Attribute)객체가 보유한 데이터 또는 상태self.name
메서드(Method)클래스에 정의된 함수, 객체의 동작def introduce(self):
생성자(Constructor)객체 생성 시 초기화 작업을 수행__init__()

2. 객체지향의 주요 특징 4가지

특징설명기억할 키워드
추상화(Abstraction)필요한 핵심 기능과 속성만 추출하여 표현핵심 요소 모델링
캡슐화(Encapsulation)데이터와 기능을 하나로 묶고 외부 접근을 제어정보 은닉, 접근 제어
상속(Inheritance)기존 클래스의 속성과 메서드를 물려받아 재사용코드 재사용, 부모·자식
다형성(Polymorphism)같은 이름의 인터페이스가 객체에 따라 다르게 동작오버라이딩, 동적 바인딩
시험 포인트 : 상속은 코드 재사용, 캡슐화는 정보 은닉, 다형성은 동일한 호출에 대한 서로 다른 동작과 연결하여 기억합니다.

3. 클래스와 객체의 관계

클래스 Student (설계도) ┌─────────────────────┐ │ 속성: name, score │ │ 메서드: introduce() │ └──────────┬──────────┘ │ 객체 생성 ┌─────────────┼─────────────┐ ▼ ▼ ▼ student1 student2 student3 홍길동 / 95 김철수 / 88 이영희 / 92 객체 객체 객체

하나의 클래스로 여러 객체를 생성할 수 있으며, 각 객체는 서로 다른 속성값을 가질 수 있습니다.

4. 생성자와 self

  • __init__() : 객체가 생성될 때 자동으로 호출되는 초기화 메서드입니다.
  • self : 메서드를 호출한 현재 객체 자신을 가리키는 매개변수입니다.
  • self.name : 현재 객체에 속한 name 속성을 의미합니다.
Python에서 self는 예약어가 아니라 관례적으로 사용하는 이름입니다. 인스턴스 메서드의 첫 번째 매개변수로 사용합니다.

5. 상속과 메서드 오버라이딩

상속은 자식 클래스가 부모 클래스의 기능을 물려받는 것이며, 오버라이딩(Overriding)은 자식 클래스에서 부모 클래스의 메서드를 같은 이름으로 다시 정의하는 것입니다.

부모 클래스 Animal │ ├── Dog → sound() : "멍멍" ├── Cat → sound() : "야옹" └── Bird → sound() : "짹짹"

super()는 자식 클래스에서 부모 클래스의 메서드나 생성자를 호출할 때 사용합니다.

6. UML(Unified Modeling Language)이란?

UML(통합 모델링 언어)은 소프트웨어 시스템을 개발하기 전에 요구사항, 구조, 객체 간 상호작용 및 처리 흐름을 그림으로 표현하기 위한 표준 모델링 언어입니다. UML은 프로그래밍 언어가 아니며, Python이나 Java 코드를 직접 실행하는 도구도 아닙니다.

왜 UML을 사용하는가?
① 개발 전에 시스템 구조를 설계할 수 있습니다.
② 개발자와 사용자 사이의 의사소통을 돕습니다.
③ 복잡한 시스템의 구성 요소와 관계를 쉽게 파악할 수 있습니다.
④ 설계 내용을 문서화하여 유지보수에 활용할 수 있습니다.

6-2. 클래스 다이어그램의 기본 구조

클래스는 일반적으로 세 부분으로 표현합니다. 맨 위에는 클래스 이름, 가운데에는 속성, 아래에는 메서드를 표시합니다.

┌─────────────────────────────┐ │ Student │ ← 클래스 이름 ├─────────────────────────────┤ │ - name : str │ ← 속성(이름 : 자료형) │ - score : int │ ├─────────────────────────────┤ │ + average() : float │ ← 메서드(이름 : 반환형) │ + introduce() : void │ └─────────────────────────────┘ 접근 제어 기호 + public : 외부에서 접근 가능 - private : 해당 클래스 내부에서 접근 제한 # protected : 해당 클래스 및 하위 클래스 중심의 접근

예를 들어 - score : int는 private 접근 범위의 score 속성이 정수형임을 의미합니다. + average() : float는 public 메서드이며 실수형 값을 반환한다는 뜻입니다.

6-3. 클래스 사이의 관계

관계의미대표 표기·예시
연관(Association)두 클래스가 서로 관련되어 객체를 참조하거나 정보를 주고받음학생 — 수강 — 강좌
집합(Aggregation)전체와 부분 관계이나 부분 객체가 전체와 독립적으로 존재할 수 있음학과 ◇— 교수
합성(Composition)강한 전체·부분 관계로 전체의 생명주기에 부분이 종속되는 관계주문 ◆— 주문항목
일반화(Generalization)상속 관계. 자식 클래스가 부모 클래스의 특성을 물려받음Dog ─▷ Animal
의존(Dependency)한 클래스가 다른 클래스를 일시적으로 사용하거나 변경에 영향을 받음주문서비스 - - > 결제서비스
연관: Student ───────── Course 집합: Department ◇──────── Professor (빈 마름모: 독립적인 부분) 합성: Order ◆──────── OrderItem (검은 마름모: 생명주기 종속) 일반화: Dog ─────────▷ Animal (빈 삼각형 화살표: 상속) 의존: OrderService - - - -> PaymentService (점선 화살표: 사용·의존)

집합과 합성의 차이는 시험에서 자주 비교되는 개념입니다. 집합은 부분 객체가 전체 객체 없이도 존재할 수 있지만, 합성은 전체와 부분의 생명주기가 강하게 연결됩니다.

6-4. 다중성(Multiplicity)

다중성은 한 클래스의 객체가 다른 클래스의 객체와 몇 개 연결될 수 있는지를 나타냅니다.

표기의미예시
1정확히 1개주문은 고객 1명에 속함
0..10개 또는 1개사원은 사물함을 사용하지 않을 수도 있음
* 또는 0..*0개 이상고객은 주문을 여러 개 가질 수 있음
1..*1개 이상주문에는 하나 이상의 항목이 존재
2..52개 이상 5개 이하정해진 범위의 구성원

7. 객체지향 설계(Object-Oriented Design)의 개념

객체지향 설계(OOD)는 요구사항을 분석한 뒤 시스템을 여러 객체와 클래스의 협력 구조로 설계하는 과정입니다. 각 객체가 어떤 책임을 갖고, 어떤 데이터를 보유하며, 다른 객체와 어떻게 메시지를 주고받는지 결정합니다.

객체지향 설계의 핵심 질문
① 어떤 객체가 필요한가? (객체 식별)
② 각 객체가 보유할 데이터는 무엇인가? (속성 설계)
③ 각 객체가 수행할 기능은 무엇인가? (메서드·책임 설계)
④ 객체 사이의 관계는 무엇인가? (연관·상속 등)
⑤ 객체 간 요청과 응답은 어떻게 이루어지는가? (메시지 설계)

7-1. 객체지향 분석과 설계의 흐름

요구사항 수집 │ ▼ 객체지향 분석(OOA) - 문제 영역과 주요 객체 식별 - 객체의 속성·기능 후보 도출 │ ▼ 객체지향 설계(OOD) - 클래스와 인터페이스 설계 - 객체 간 관계와 메시지 정의 - 데이터 및 책임 배분 │ ▼ 구현(OOP) - Python 등의 언어로 클래스 작성 - 객체 생성 및 메서드 구현 │ ▼ 테스트 및 유지보수
단계주요 활동산출물 예시

객체지향 분석(OOA)객체, 속성, 책임 및 관계 파악개념 클래스 모델
객체지향 설계(OOD)클래스 구조, 인터페이스, 메시지, 알고리즘 설계클래스·시퀀스 다이어그램
구현설계 내용을 프로그래밍 언어로 작성소스 코드
테스트기능과 객체 간 상호작용 검증테스트 결과

7-2. 좋은 객체지향 설계의 원칙

원칙설명설계 예시
단일 책임 원칙(SRP)클래스는 하나의 핵심 책임에 집중학생 정보 관리와 성적 계산 책임 분리
개방-폐쇄 원칙(OCP)확장에는 열려 있고 변경에는 닫혀 있어야 함새 결제 방식을 기존 코드의 큰 수정 없이 추가
리스코프 치환 원칙(LSP)자식 객체는 부모 객체를 사용하는 위치에 대체 가능해야 함부모 유형으로 처리해도 자식 객체가 정상 동작
인터페이스 분리 원칙(ISP)사용하지 않는 기능까지 강제로 의존하지 않도록 인터페이스를 작게 분리프린터 기능과 스캐너 기능을 분리
의존 역전 원칙(DIP)구체적인 구현보다 추상화에 의존하도록 설계특정 결제 클래스 대신 결제 인터페이스에 의존

위 다섯 원칙을 SOLID 원칙이라고 합니다. 이는 유지보수와 확장성이 높은 객체지향 설계를 위한 대표적인 설계 지침입니다.

7-3. 응집도와 결합도

개념설명바람직한 설계
응집도(Cohesion)하나의 모듈 내부 요소들이 같은 목적을 위해 얼마나 밀접하게 구성되어 있는가높을수록 좋음
결합도(Coupling)모듈 사이의 의존 관계가 얼마나 강한가낮을수록 좋음
시험 핵심 : 좋은 모듈 설계는 일반적으로 높은 응집도와 낮은 결합도를 지향합니다.

7-4. 객체지향 설계 예시: 학생 성적 관리 시스템

요구사항: 학생의 이름과 과목별 점수를 저장하고 평균을 계산하며, 성적 정보를 출력합니다.

┌────────────────────────────┐ │ Student │ ├────────────────────────────┤ │ - name : str │ │ - scores : list │ ├────────────────────────────┤ │ + average() : float │ │ + print_info() : void │ └────────────────────────────┘ │ │ 학생 객체 생성 ▼ Student("홍길동", [90, 80, 100]) │ ├── average() → 90.0 └── print_info() → 학생 정보 출력

이 설계를 Python 코드로 구현하면 다음과 같습니다.

설계 예제 · Student 클래스
class Student:
    def __init__(self, name, scores):
        self.name = name
        self.scores = scores

    def average(self):
        return sum(self.scores) / len(self.scores)

    def print_info(self):
        print("이름:", self.name)
        print("과목 점수:", self.scores)
        print("평균:", self.average())

student = Student("홍길동", [90, 80, 100])
student.print_info()
실행 결과
이름: 홍길동
과목 점수: [90, 80, 100]
평균: 90.0

Ⅱ. 필기시험 대비 객관식 문제

각 문항의 답을 선택한 후 정답 및 해설 버튼을 눌러 확인하세요. 실제 기출문제를 그대로 옮긴 것이 아니라 핵심 개념을 바탕으로 구성한 기출형 연습문제입니다.

문제 1. 객체지향 프로그래밍에서 객체를 생성하기 위한 설계도에 해당하는 것은?

정답: ② 클래스
클래스는 객체를 생성하기 위한 설계도이며, 인스턴스는 클래스로부터 생성된 객체입니다.

문제 2. Python에서 객체 생성 시 속성을 초기화하기 위해 사용하는 메서드는?

정답: ③ __init__()
인스턴스 생성 시 자동으로 호출되어 초기 속성값을 설정하는 초기화 메서드입니다.

문제 3. 객체지향의 특징 중 데이터와 관련 메서드를 하나로 묶고 외부 접근을 제어하는 것은?

정답: ④ 캡슐화
캡슐화는 데이터와 기능을 묶고 접근을 제어하여 내부 구현을 보호하는 개념입니다.

문제 4. 부모 클래스의 메서드를 자식 클래스에서 같은 이름으로 재정의하는 것은?

정답: ② 오버라이딩
오버라이딩은 상속 관계에서 자식 클래스가 부모 클래스의 메서드를 재정의하는 것입니다.

문제 5. Python 인스턴스 메서드에서 현재 객체를 참조하는 관례적인 매개변수 이름은?

정답: ③ self
self는 현재 인스턴스를 참조합니다. super()는 부모 클래스의 메서드에 접근할 때 사용합니다.

문제 6. 객체지향의 다형성에 대한 설명으로 가장 적절한 것은?

정답: ③
다형성은 동일한 메서드 호출이 객체의 유형에 따라 서로 다른 동작을 수행할 수 있는 특징입니다.

문제 7. 자식 클래스에서 부모 클래스의 메서드를 호출할 때 사용하는 Python 함수는?

정답: ② super()
super()를 이용하여 부모 클래스의 메서드 또는 생성자를 호출할 수 있습니다.

문제 8. UML 클래스 다이어그램에서 일반적으로 private 접근 제어자를 나타내는 기호는?

정답: ③ -
UML에서 +는 public, -는 private, #는 protected를 나타냅니다.

문제 9. 다음 중 상속의 주요 목적으로 가장 적절한 것은?

정답: ①
상속은 기존 클래스의 기능을 재사용하고 자식 클래스에서 기능을 확장할 수 있도록 합니다.

문제 10. 다음 코드의 실행 결과로 옳은 것은?

class Counter:
    def __init__(self, value):
        self.value = value

a = Counter(10)
b = Counter(20)
print(a.value + b.value)
정답: ③ 30
a.value는 10, b.value는 20이므로 두 속성의 합은 30입니다. 각 객체는 독립적인 인스턴스 속성을 가집니다.

문제 11. UML 클래스 다이어그램에서 클래스의 속성과 메서드를 구분하여 표현할 때 일반적으로 사용하는 구획 수는?

정답: ③ 3개
클래스 이름, 속성, 메서드의 세 구획으로 표현하는 것이 일반적입니다.

문제 12. UML에서 전체 객체와 부분 객체의 생명주기가 강하게 연결되는 관계는?

정답: ③ 합성
합성은 전체와 부분의 생명주기가 강하게 연결된 관계이며 UML에서 검은 마름모로 표시합니다.

문제 13. UML 다이어그램 중 객체 간 메시지 교환을 시간 순서에 따라 표현하는 것은?

정답: ② 시퀀스 다이어그램
시퀀스 다이어그램은 시간의 흐름에 따른 객체 간 메시지 전달 순서를 나타냅니다.

문제 14. 객체지향 설계에서 일반적으로 바람직한 모듈의 특성은?

정답: ②
모듈 내부는 높은 응집도로 구성하고 모듈 간 의존성은 낮은 결합도를 지향합니다.

문제 15. SOLID 원칙 중 클래스가 하나의 핵심 책임에 집중해야 한다는 원칙은?

정답: ① SRP
단일 책임 원칙(SRP)은 클래스가 하나의 변경 이유 또는 핵심 책임을 갖도록 설계하는 원칙입니다.

실습 5. 객체 정렬과 lambda

중급학생 객체를 점수 기준으로 내림차순 정렬합니다.

Python 코드 5 · 객체 정렬
class Student:
    def __init__(self, name, score):
        self.name = name
        self.score = score

students = [
    Student("홍길동", 95),
    Student("김철수", 82),
    Student("이영희", 100),
    Student("박민수", 90)
]

# score를 기준으로 내림차순 정렬
students.sort(key=lambda s: s.score, reverse=True)

for s in students:
    print(s.name, s.score)
실행 결과
이영희 100
홍길동 95
박민수 90
김철수 82

실습 6. 클래스 상속과 super()

중급부모 클래스의 생성자를 호출하고 자식 클래스의 속성을 추가합니다.

Python 코드 6 · 상속
class Person:
    def __init__(self, name):
        self.name = name

    def introduce(self):
        print("이름:", self.name)

class Student(Person):
    def __init__(self, name, major):
        super().__init__(name)
        self.major = major

    def study(self):
        print(self.name, "학생의 전공:", self.major)

s = Student("홍길동", "AI소프트웨어")
s.introduce()
s.study()
실행 결과
이름: 홍길동
홍길동 학생의 전공: AI소프트웨어

실습 7. 메서드 오버라이딩과 다형성

중급자식 클래스가 부모 클래스의 메서드를 재정의합니다.

Python 코드 7 · 오버라이딩
class Animal:
    def sound(self):
        print("동물 소리")

class Dog(Animal):
    def sound(self):
        print("멍멍")

class Cat(Animal):
    def sound(self):
        print("야옹")

animals = [Dog(), Cat(), Animal()]

for animal in animals:
    animal.sound()
실행 결과
멍멍
야옹
동물 소리

실습 8. 캡슐화와 접근 메서드

심화이름 앞에 밑줄 두 개를 붙인 속성과 메서드를 이용해 내부 데이터에 직접 접근하는 것을 제한하는 예시입니다. Python의 이름 맹글링은 완전한 보안 기능은 아닙니다.

Python 코드 8 · 캡슐화
class BankAccount:
    def __init__(self, balance):
        self.__balance = balance

    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount

    def get_balance(self):
        return self.__balance

account = BankAccount(10000)
account.deposit(5000)

print("잔액:", account.get_balance())
실행 결과
잔액: 15000
