1. 운영체제와 프로세스의 기본 개념

1-1. 운영체제란?

운영체제(Operating System, OS)는 사용자와 응용 프로그램이 컴퓨터 하드웨어를 효율적으로 사용할 수 있도록 관리하는 시스템 소프트웨어입니다.

1-4. 프로세스 제어 블록(PCB)

프로세스 제어 블록(Process Control Block, PCB)은 운영체제가 프로세스를 관리하기 위한 자료구조입니다. 프로세스 상태, 프로그램 카운터, CPU 레지스터, 스케줄링 정보, 메모리 관리 정보, 입출력 상태 등이 저장됩니다.

문맥 교환(Context Switching)은 CPU가 다른 프로세스로 전환될 때 현재 프로세스의 실행 정보를 저장하고 다음 프로세스의 정보를 복원하는 과정입니다. 문맥 교환은 CPU 시간을 소비하는 오버헤드가 발생합니다.

2. CPU 스케줄링(CPU Scheduling)

2-1. 개념과 목적

CPU 스케줄링은 준비 큐에 있는 프로세스 중 다음에 CPU를 사용할 프로세스를 선택하는 기능입니다. CPU 이용률과 처리량을 높이고 대기 시간, 반환 시간, 응답 시간을 줄이는 것이 주요 목표입니다.

비선점형(Non-preemptive)

프로세스가 자발적으로 CPU를 반납하거나 종료할 때까지 실행합니다.

대표: FCFS, 비선점형 SJF, HRN

선점형(Preemptive)

운영체제가 실행 중인 프로세스에서 CPU를 회수해 다른 프로세스에 할당할 수 있습니다.

대표: RR, SRT, 선점형 우선순위

2-2. 주요 알고리즘

알고리즘선택 기준선점특징
FCFS
First Come First Served		먼저 도착한 순서비선점단순하지만 긴 작업이 앞에 있으면 호위 효과 발생 가능
SJF
Shortest Job First		CPU 실행 시간이 가장 짧은 작업기본형은 비선점평균 대기 시간 최소화에 유리하나 기아 가능
SRT
Shortest Remaining Time		남은 실행 시간이 가장 짧은 작업선점새 작업 도착 시 남은 시간 비교 후 선점 가능
RR
Round Robin		순환 큐에서 시간 할당량만큼 실행선점시분할 시스템에 적합, 시간 할당량이 중요
HRN
Highest Response Ratio Next		응답률이 가장 높은 작업비선점대기 시간이 길수록 우선순위가 높아져 기아 완화
Priority우선순위가 높은 작업선점·비선점 모두 가능낮은 우선순위 작업의 기아 가능

2-3. 시간 계산의 핵심 용어

용어계산식의미
반환 시간(Turnaround Time)완료 시간 − 도착 시간도착부터 완료까지의 전체 시간
대기 시간(Waiting Time)반환 시간 − CPU 실행 시간준비 큐 등에서 기다린 누적 시간(단순 CPU burst 문제 기준)
응답 시간(Response Time)최초 CPU 시작 시간 − 도착 시간도착 후 처음 CPU를 사용하기까지의 시간
실행 시간(Burst Time)문제에서 주어진 CPU 사용 시간CPU를 실제로 사용하는 총 시간

3. 교착상태(Deadlock)

3-1. 교착상태란?

둘 이상의 프로세스가 서로 상대방이 점유한 자원을 기다리면서 관련 프로세스들이 더 이상 진행하지 못하는 상태입니다.

P1
프린터 보유
→
스캐너 대기
P2
스캐너 보유
→
프린터 대기

P1과 P2가 서로 상대방의 자원을 기다리는 순환 대기

3-2. 교착상태 발생의 네 가지 필요조건

조건영문설명예
상호 배제Mutual Exclusion자원을 한 번에 한 프로세스만 사용한 대의 프린터
점유와 대기Hold and Wait자원을 가진 채 다른 자원을 기다림프린터를 가진 채 스캐너 대기
비선점No Preemption사용 중인 자원을 강제로 빼앗을 수 없음작업 중인 프린터 강제 회수 불가
환형 대기Circular Wait프로세스가 원형으로 서로의 자원을 기다림P1→R2→P2→R1→P1
시험 핵심: 네 조건이 동시에 성립하면 교착상태가 발생할 수 있는 필요조건이 충족됩니다. 하나 이상의 조건을 깨면 교착상태를 예방할 수 있습니다.

3-3. 자원 할당 그래프

프로세스는 원, 자원은 사각형으로 표현합니다. 프로세스에서 자원으로 향하는 화살표는 요청, 자원에서 프로세스로 향하는 화살표는 할당을 뜻합니다.

프린터
→

→

→
P2
→

단일 인스턴스 자원 시스템에서 순환이 있으면 교착상태입니다. 자원 인스턴스가 여러 개라면 순환만으로 교착상태라고 단정할 수 없습니다.

3-4. 교착상태 해결 방법

방법핵심 전략대표 사례
예방(Prevention)네 가지 필요조건 중 하나가 성립하지 않도록 설계자원 요청 순서 고정
회피(Avoidance)자원 할당 후에도 안전 상태가 유지되는지 검사은행원 알고리즘
발견(Detection)교착상태가 발생했는지 검사자원 할당 관계 분석
회복(Recovery)발생한 교착상태를 해소프로세스 종료, 자원 선점

3-5. 은행원 알고리즘(Banker's Algorithm)

자원을 할당한 뒤에도 모든 프로세스가 완료될 수 있는 순서가 존재하는지 확인하는 교착상태 회피 알고리즘입니다.

안전 상태(Safe State)란 현재 가용 자원과 프로세스들의 최대 추가 요구량을 고려했을 때 모든 프로세스를 완료할 수 있는 순서가 하나 이상 존재하는 상태입니다.

프로세스최대 요구량현재 할당량추가 필요량
P1734
P2523
P3321

가용 자원이 3개라면 P3(추가 1개 필요)을 먼저 완료할 수 있습니다. P3이 종료되어 자원 2개를 반환하면 가용 자원은 5개가 됩니다. 이어 P2, P1을 완료할 수 있으므로 안전 순서는 P3 → P2 → P1입니다.

3-6. 교착상태와 기아의 차이

구분교착상태(Deadlock)기아(Starvation)
원인프로세스 사이의 자원 순환 대기특정 프로세스가 자원 할당에서 계속 밀림
진행교착된 프로세스들은 진행 불가다른 프로세스는 진행 가능
대응예방·회피·발견·회복공정한 스케줄링, 에이징(Aging)

4. 메모리 관리(Memory Management)

4-1. 메모리 계층

메모리 관리는 프로세스가 사용할 메모리 공간을 할당하고 보호하며 회수하는 기능입니다.

4-2. 연속 할당과 비연속 할당

연속 메모리 할당

프로세스에 연속된 메모리 영역을 할당합니다. 외부 단편화가 발생할 수 있습니다.

비연속 메모리 할당

프로세스를 여러 메모리 영역에 나누어 배치합니다. 페이징과 세그먼테이션이 대표적입니다.

4-3. 단편화(Fragmentation)

내부 단편화(Internal Fragmentation)

할당된 블록 내부에서 실제로 사용하지 않는 공간입니다.

외부 단편화(External Fragmentation)

사용 가능한 공간이 여러 작은 구멍으로 흩어져 큰 연속 공간을 확보하지 못하는 현상입니다.

4-6. 가상 메모리와 요구 페이징

가상 메모리(Virtual Memory)는 프로세스에 실제 물리 메모리보다 큰 주소 공간을 제공하는 메모리 관리 기법입니다. 필요한 부분을 주기억장치에 적재해 실행합니다.

요구 페이징(Demand Paging)은 페이지가 실제로 필요해질 때 주기억장치에 적재하는 방식입니다.

페이지 접근
→
RAM에 있는가?
예: 페이지 적중(Hit)

RAM에 이미 있으므로 바로 접근을 계속합니다.

아니요: 페이지 부재(Page Fault)

운영체제가 필요한 페이지를 보조기억장치에서 가져오는 절차를 수행합니다.

페이지 부재 처리의 일반적인 흐름은 부재 확인 → 필요한 페이지 위치 확인 → 빈 프레임 확보(필요하면 페이지 교체) → 페이지 적재 → 페이지 테이블 갱신 → 중단된 명령 재시작입니다.

4-7. 페이지 참조순서와 페이지 부재

페이지 참조순서(Page Reference String)는 프로그램이 실행되면서 접근하는 페이지 번호의 순서입니다. 1, 2, 3, 1, 4, 2, 5는 페이지 1, 2, 3, 다시 1, 이어서 4, 2, 5를 요청한다는 뜻입니다.

중요한 구분
참조순서는 프로그램이 요청하는 페이지 번호의 나열이고, 프레임은 그 페이지를 RAM에 담는 실제 공간입니다. 시작 시 프레임이 비어 있다면 1, 2, 3 요청은 모두 페이지 부재입니다. 1, 2, 3이 적재된 뒤 다시 1을 요청하면 페이지 적중입니다.

4-8. 페이지 교체 알고리즘

알고리즘교체 대상기억할 점
FIFO
First In First Out		가장 먼저 들어온 페이지들어온 순서를 기준으로 교체
LRU
Least Recently Used		가장 오랫동안 사용되지 않은 페이지과거의 최근 사용 시점을 기준으로 교체
LFU
Least Frequently Used		사용 횟수가 가장 적은 페이지참조 빈도를 기준으로 교체
OPT
Optimal		앞으로 가장 오랫동안 사용되지 않을 페이지미래 참조를 알아야 하는 이론적 최적 기준

4-9. FIFO 페이지 교체 실습기

페이지 참조순서와 프레임 수를 입력하고 계산하면 각 요청 시점의 프레임 상태를 확인할 수 있습니다.

결과가 여기에 표시됩니다.
페이지 부재율 = 페이지 부재 횟수 ÷ 전체 페이지 참조 횟수 × 100
위 예제의 FIFO 결과는 프레임 3개 기준 부재 5회, 적중 2회이며 부재율은 약 71.43%입니다.
